# 适配器运行时来源与升级核验

平台 SDK 的实际运行来源由宿主环境决定，仓库中的适配器包装层不等于 SDK 源码。维护依赖前应先确认当前解释器实际加载的发行包、版本与模块路径，再判断需要修改的是包装层、外部依赖还是明确分发的 vendored 代码。

## 核对实际来源

- 用 `importlib.metadata` 读取发行包名称与版本，用 `importlib.import_module` 检查实际导入模块的 `__file__`。
- 对照安装依赖声明、NoneBot CLI 安装步骤和宿主虚拟环境；不要把另一工作树、系统 Python 或测试环境的包版本当作当前运行事实。
- 检查仓库是否实际包含对应 SDK 源码、许可证和来源记录。没有 vendored 源码时，不要将外部依赖的修复描述为仓库内已移植。
- `nonebot_plugin_xiuxian_3/adapters/` 中的适配器负责事件归一化和消息投递；共享业务只接收 xiuxian3 的 `CommandContext` 等 DTO。

## 评估上游变更

1. 固定上游 tag 或 commit，并记录来源、许可证、原始文件指纹和依赖约束。
2. 对照当前实际安装版本核实补丁适用范围；上游主干差异只能作为候选，不表示当前环境已包含该行为。
3. 若确需分发第三方源码，放入明确隔离的命名空间，保留许可证及本地修改说明；不得直接改 site-packages 或将平台对象带入领域层。
4. 为受影响的事件字段、生命周期和消息能力补适配器短合同。测试应覆盖事件到共享 application 的边界、失败重试和能力降级；不以共享业务测试替代适配器验收。

涉及本地协议修改时，对共同祖先、本地实现和目标上游做三方比较。引用索引、事件缺字段回退、
消息序号和生命周期不能靠覆盖文件解决；每项冲突须说明保留行为及对应测试。候选补丁在确认
实际加载来源和依赖约束前不进入发行包，不将候选或另一宿主的行为写成当前能力。

## 验收边界

OneBot 与 QQ 共用 application 和 repository。平台差异只在归一化、权限上下文及结果呈现处处理。发送消息失败只能重试投递，不能重放资产用例；未知场景不能进入写路径。仓内 fixture 可以证明归一化和路由合同，但不能证明真实账号权限、网络连接或客户端呈现。

| 边界 | 必要验证 |
|:--|:--|
| QQ | SDK 事件解析、群/私聊/频道身份、提及与引用索引、空消息、interaction ACK、消息序号、Markdown/键盘和投递失败重试 |
| OneBot V11 | 群/私聊事件、消息段与合并转发、API 超时与重连、事件去重和 application 接线 |
| 共享上下文 | operation key 隔离、未知场景只读、可重试错误不重复业务写入 |

`test/test_adapter_normalization.py`、`test/test_adapter_simulation.py` 与 `test/test_messaging.py`
提供归一化、消息和投递合同的定向入口。真实 SDK 生命周期与外部平台结果需另有运行证据。

实现和错误语义见[适配器复用与验收](extensions/adapters/reuse.md)；当前玩家可用范围见[当前可用能力](availability.md)。
