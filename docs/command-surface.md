# 命令与交互面

## 1. 兼容范围

干净主分支（`main`，盘点提交 `97f43ac`）包含约 640 条 `on_command`
声明，存在同名命令由不同子模块处理、别名重叠和管理员命令与用户命令共存
的情况。新项目不得凭感觉重命令名：实现每个垂直切片前，应从参考运行实例
导出一次“主命令、别名、权限、参数语法、回复类型”的冻结清单，作为测试夹具。

命令清单是协议，不是实现。新项目可以使用完全不同的 matcher 组织方式，
但必须通过显式 manifest 确保一个命令/别名只有一个所有者。

## 3. 交互契约

- 参数解析发生在 adapter 层，领域用例接收已校验的 DTO。
- 对同一用户的资产写入必须返回可读的成功、拒绝、冷却、过期或处理中状态。
- 按钮回调与文本命令调用同一用例；按钮参数不能绕过权限、次数和幂等检查。
- 带引用回复、Markdown、键盘、图片和合并转发属于消息能力，不进入领域层。
- 帮助命令必须由 manifest 生成，避免实现和帮助文案长期漂移。

## 4. 兼容清单格式

后续实现应为每条命令记录：

| 字段 | 含义 |
|:--|:--|
| `name` | 主命令（不含前缀） |
| `aliases` | 保留别名；大小写/空白归一化规则 |
| `permission` | `user`、`group`、`admin`、`superuser` |
| `argument_schema` | 位置参数、可选参数、JSON/按钮参数 |
| `scene` | 群、私聊、频道群、频道私信 |
| `reply_modes` | 文本、Markdown、图片、键盘、引用 |
| `cooldown` | 用户/群/全局限流和业务冷却 |
| `operation` | 是否产生资产变化及幂等键要求 |
