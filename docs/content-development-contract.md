# 通用功能开发合同

本文规定跨领域一致的事务、随机、幂等、错误处理和数据库变更要求。玩法内容与可调参数的唯一来源见[数据内容开发合同](content-data-contract.md)；玩家可见文字见[消息与文案规范](messaging-copywriting.md)；当前开放范围见[当前开发状态](current-status.md)。

方案编号只用于对照文档，不是运行时开关、内容字段或数据库兼容标记。不得将文档版本号复制到 Python 常量、JSON、玩家存档或结算快照。运行快照只保存重放和结算真正需要的业务输入、冻结参数、随机证据和实际结果。

## 1. 事务与资产

- 所有灵石、修为、体力、精力、物品、耐久、声望、贡献和奖励变化必须在同一个数据库事务中完成。
- 读取、预览和帮助命令不创建资产 operation，不消耗资源，不占用次数。
- 写入前在事务内重新读取角色和目标状态，校验权限、前置、余额、库存、冷却及配额；任一检查失败都不得产生部分变化。
- `operation_id` 是写操作的幂等键。相同 ID 和相同输入回放原结果；相同 ID 和不同输入返回冲突；重试不得重新抽奖或重复扣发资产。
- 领域 repository 负责领域查询和写入；schema、连接策略、事务基础设施和迁移由 `persistence/` 管理。

## 2. 随机与运行快照

- 随机候选、适用因子、权重、奖励池和保底参数由 `data/` 配置；代码只实现通用过滤与抽取算法。
- 随机使用服务端种子。事务中保存重放所需的种子/证据、抽中的稳定键和实际结果。
- 运行中会话必须冻结后续结算所需的业务事实，避免配置变化、重启或适配器切换改变已开始的行动。
- 没有候选内容时返回明确的无可用结果，不静默采用 Python 内置奖池或默认任务。

## 3. 错误与投递

- 配置错误、缺失引用和不支持的内容必须在加载或校验阶段明确失败，不跳过记录、不吞异常、不回退到另一份硬编码表。
- 领域错误转换为稳定错误码和玩家可执行的说明；异常详情、内部字段和调用栈写日志，不直接发送给玩家。
- 消息渲染或适配器投递失败不能回滚已成功提交的业务事务，也不能触发重复结算。
- QQ、OneBot V11、Web 和 CLI 只负责输入校验与结果呈现；业务权限和结算统一进入 application 用例。

## 4. 数据库变更

项目尚未正式发布，schema 可以直接重构，不实现无业务必要的旧表、旧字段或旧格式兼容层。修改 schema 时同步更新 schema 定义、领域 repository、测试夹具和文档，并在临时数据库上验证完整功能路径。

测试数据库必须位于临时目录或明确指定的测试路径。任何开发、安装或运行命令都不得自动删除用户数据目录中的数据库。需要清空本地开发数据时，先备份并由开发者明确指定目标文件；提交中不包含本机数据库文件。

## 5. 验收

每项写功能至少验证：成功、前置不足、资源不足、重复 operation、同 ID 不同输入、随机重放和数据库异常回滚。涉及内容矩阵的功能还要验证边界因子、无候选、多个候选、权重变化以及奖励原子性。

新增玩家入口前确认状态页允许开放。所有玩家消息符合[消息与文案规范](messaging-copywriting.md)，并在 QQ 与 OneBot V11 测试中验证适配器能力降级不改变业务结果。
