# 内容方案整理说明

过去按阶段编号分散的内容方案不再作为工程开发入口。当前开发和验收只看：

- [完整内容开发总表](content-development.md)：稳定键、开放范围、依赖和验收裁决；
- [当前开发状态](current-status.md)：已经接入运行时、关闭和待开发能力；
- 各领域 `README.md`、`model.md`、`workflow.md`、`use-cases.md`：当前实现合同。

这些编号只帮助阅读者对照原始方案，不是运行时开关、存档版本或开发顺序；不得复制为代码常量、
JSON 字段、数据库结算版本或玩家可见文案。内容配置只存储业务字段。

新增或修改玩法时直接更新 `content-development.md`、对应域的当前
`README.md`/`model.md`/`workflow.md`，并同步 `current-status.md`；不要再创建按版本拆分的内容文档。

仓库中仍保留部分旧的 `content-v*.md` 文件，尚未逐条核对并清除。它们不是当前规则来源；后续整理
时应先把仍有效的业务信息并入上述权威文档，再移除重复旧页，不得假设全部细节已经自动合并。

## 阅读规则

1. 新功能先读 `current-status.md`，确认状态允许接入。
2. 再读对应领域 README 和模型/流程/用例文档。
3. 修改内容只改 `data/` 业务字段，不在命令处理器中新增内容参数或文档版本常量。
