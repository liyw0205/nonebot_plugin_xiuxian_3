# 内容快照合并说明

内容快照不再作为工程开发入口。原先各领域分散的 `content-v0.1.md` 至
`content-v0.6.md` 已合并到统一内容基线；旧文件保留在原目录仅用于历史回放和链接兼容，
不得再作为并列规范或新增功能入口。开发和验收只看：

- [完整内容开发总表](content-development.md)：稳定键、开放范围、依赖和验收裁决；
- [当前开发状态](current-status.md)：已经接入运行时、关闭和待开发能力；
- 各领域 `README.md`、`model.md`、`workflow.md`、`use-cases.md`：当前实现合同。

## 快照边界

| 快照 | 主要范围 | 当前判断 |
|:--|:--|:--|
| v0.1 | 新手流程、感气/聚气/筑基、玄天起步区和基础生产 | 基础闭环已接入 |
| v0.2 | 金丹、洞天扩展、成熟市场和设施 | 部分接入，按状态页为准 |
| v0.3 | 元婴、魔界/妖界、多人副本和跨界活动 | 部分接入，按状态页为准 |
| v0.4 | 化神、领域和远古洞天 | 部分接入，按状态页为准 |
| v0.5 | 炼虚、虚空航道和档案遗迹 | 部分接入，按状态页为准 |
| v0.6 | 合道、渡劫、道源和终局准备 | 部分接入，终局开放边界以状态页为准 |

历史快照中的版本号只用于解释旧操作和迁移数据，不是启动开关，也不应复制到新业务代码。
新内容的版本元数据集中在 `data/内容版本.json`，内容文件本身只保留业务字段。

新增或修改玩法时直接更新 `content-development.md`、对应域的当前
`README.md`/`model.md`/`workflow.md`，并同步 `current-status.md`；不要再创建新的
`content-v*.md` 文件。

## 阅读规则

1. 新功能先读 `current-status.md`，确认不是 `locked` 或 `contract`。
2. 再读对应领域 README 和模型/流程/用例文档。
3. 需要历史参数时才查对应快照归档；快照不能覆盖当前状态页。
4. 修改内容只改 `data/` 业务字段和 `data/内容版本.json`，不要在命令处理器中新增版本常量。
