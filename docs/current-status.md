# 当前开发状态

本文只回答一个问题：**当前分支哪些能力已经可以运行，哪些仍然只是规则或内容合同**。
它不是玩法规则的第二份定义；规则、数值、稳定键和完整路线仍以[完整内容开发总表](content-development.md)
及各域的 `model.md`、`workflow.md`、`use-cases.md` 为准。

## 1. 状态定义

| 状态 | 含义 | 是否允许新增运行时入口 |
|:--|:--|:--:|
| `open` | 已有 application 用例、持久化、幂等和适配器测试，可供玩家使用 | 是 |
| `partial` | 已有可玩的局部流程，但声明的内容奖励、来源或验收仍未闭合 | 否；只补齐既有合同，不扩大玩法面 |
| `contract` | 已有完整规则、稳定键和测试夹具，但尚未接入运行时 | 否 |
| `locked` | 已登记内容或接口，前置条件尚未满足，统一返回内容未开放 | 否 |
| `planned` | 已列入开发路线，尚未完成规则闭合 | 否 |

`content-v0.1` 至 `content-v0.6` 是发布快照，不代表当前状态，也不代表代码开发顺序。
快照中的 `open` 只表示该版本发布时计划开放；本文件中的 `open` 才表示当前代码已经接入。

终局资源的默认数值闭合已由公式测试核验：三试炼提供道果进度 530、`ascension_merit=550`；三项
道源任务提供道果进度 470、`ascension_merit=450`，另给世界功勋 1,000。道源核验会在当前
35 天 UTC 窗口内消费守界胜场、公共项目奖励或师徒毕业 operation；目标与奖励读取任务 JSON，首笔有效进度冻结，达到目标（默认 3 次）时发奖一次。
渡劫 L9→L10 要求三项任务在至少一个共同赛季分别达到各自历史快照的目标，但该赛季可以已经结束。道果加工/天劫保护阵配方只允许在道源门创建，飞升凭证配方只允许在天劫台创建，所有订单均冻结创建地点快照。
道源门已从虚空档案遗迹接入 60 分钟移动，会原子扣除 20 体力和 2 个道果碎片，
并按 UTC 日限一次；虚空档案航道结算会正式把角色位置写为 `void.archive_ruins`，因此道源门来源条件可由玩家移动链满足；天劫台现从道源门接入 30 分钟移动，渡劫 L3 可创建行程并消耗 1 张移动凭证，试炼只能在天劫台启动且另扣试炼凭证。天劫凭证现由合道许可领取和三项道源任务当季 3/3 完成事务发放，共 4 张覆盖移动与三次试炼；三试炼成功后可在天劫台生产飞升凭证，避免无法返回道源门的路线断点。道果加工和天劫保护阵仍在道源门生产。配方、战斗会话与状态推进均以创建时冻结的业务参数为准。终局胜利直接进入飞升路候选状态，不再要求二次移动扣证；终局战支持最多五人、凭证托管/返还、半血选择、重启恢复、逐成员奖励和留界结局历史；终局赛季按需冻结匿名三榜，领奖/逾期补发已通过 QQ/OneBot 适配器测试。新角色公开命令链现已由 QQ 官方与 OneBot V11 从新手推进至渡劫 L10，完成三试炼、飞升凭证、终局战和飞升结局；其余尚待工作以本节清单为准。

## 5. 开发顺序

开发按可独立验收的垂直切片推进，不按 `content-v0.1`、`content-v0.2` 逐个版本搬运：

1. **持续稳定**：迁移、回放、并发、资产锁和 QQ/OneBot 适配器契约；任何已开放切片出现回归时优先修复。
2. **已完成**：自动回合最小闭环，包括训练傀儡观战、单人 PVE、可回放会话、超时/失败恢复和真实战斗奖励唯一性；后续遭遇战只能复用该会话证据，不能补写资格标记。
3. **已完成**：化神/炼虚许可生产者，包括任务组件、来源 operation、自动战斗证据、材料扣除、重复请求和 QQ/OneBot 测试；新角色专项已进一步验证炼虚许可、突破与炼虚 L10。
4. **终局链已完成**：五人终局战、凭证生命周期、恢复/回放、半血分支和 QQ/OneBot 验收已接入；新角色公开命令链已进一步完成渡劫 L1→L10、三次试炼、飞升凭证生产、终局战和飞升结局。
5. **已完成**：赛季候选、三榜、匿名展示和奖励结算，以及正式异步 `1v1` `arena.spar`（快照、反刷、自动回合、回放、资产隔离和 QQ/OneBot 验收）。
6. **已完成**：`arena.rank`、`arena.practice` 的模式配额、同段/授权匹配、零资产练习、反刷、回放和 QQ/OneBot 验收。
7. **已完成**：对称 2v2/3v3 `arena.team`；复用已确认双人或三人竞技队伍，保存队伍快照、同段匹配、服务端自动回合、独立回放、积分更新和 QQ/OneBot 验收。
8. **已完成**：2v3 非对称多方 PvP；双方使用独立队伍快照和服务端自动回合，验证成员隔离、回放和 QQ/OneBot 端到端流程。
9. **已完成**：竞技场图鉴/地区名望正式投影；每名参与者写入不可变竞技场图鉴首见、活动记录和地方名望流水，投影与对局同事务、可重放且失败回滚。
10. **已完成**：跨服匹配前置数据层；平台身份路由、只读赛季冻结快照和结算审计已接入，但不开放跨服匹配或身份合并。
11. **已完成**：跨服恢复演练与观测审计；竞技场备份工件受数据根路径约束，恢复前创建独立快照，恢复后执行 SQLite 完整性、外键、投影/身份/赛季/审计引用校验；历史 operation 可重放且不重复投影，失败保留原库并记录 request/operation、版本、结果、失败原因和耗时。

## 6. 文档维护规则

- 改玩法边界、境界或跨域依赖：先改 `content-development.md`。
- 改实体、状态机或用例契约：改对应域的 `model.md`、`workflow.md` 或 `use-cases.md`。
- 改当前实现状态：只改本文，并在对应域 README 保留链接，不复制整张状态表。
- 改玩法参数：直接更新 `content-development.md`、对应域文档和现行 JSON，并同步更新消费测试；未发布内容不维护旧格式、旧字段或兼容迁移。
- 代码、命令处理器和测试不得自行创建与文档冲突的第二套规则。
