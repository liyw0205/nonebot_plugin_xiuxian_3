# 当前开发状态

本文只回答一个问题：**当前分支哪些能力已经可以运行，哪些仍然只是规则或内容合同**。
它不是玩法规则的第二份定义；规则、数值、稳定键和完整路线仍以[完整内容开发总表](content-development.md)
及各域的 `model.md`、`workflow.md`、`use-cases.md` 为准。

## 1. 状态定义

| 状态 | 含义 | 是否允许新增运行时入口 |
|:--|:--|:--:|
| `open` | 已有 application 用例、持久化、幂等和适配器测试，可供玩家使用 | 是 |
| `contract` | 已有完整规则、稳定键和测试夹具，但尚未接入运行时 | 否 |
| `locked` | 已登记内容或接口，前置条件尚未满足，统一返回内容未开放 | 否 |
| `planned` | 已列入开发路线，尚未完成规则闭合 | 否 |

`content-v0.1` 至 `content-v0.6` 是发布快照，不代表当前状态，也不代表代码开发顺序。
快照中的 `open` 只表示该版本发布时计划开放；本文件中的 `open` 才表示当前代码已经接入。

## 3. 当前未开放

以下内容可以在文档中有完整设计，但当前不能创建可运行的业务会话：

| 范围 | 当前状态 | 开放前置 |
|:--|:--|:--|
| 自动回合战斗 | `contract`/`locked` | 角色、属性、装备、技能、队伍、事务和回放门槛全部通过 |
| 单人/多人 PVE | `contract`/`locked` | 战斗运行时后置；只能使用规则、接口和测试夹具 |
| 1v1/多方 PvP | `contract`/`locked` | 服务端自动选行动，客户端不得提交攻击、技能、目标或结果 |
| 秘境、遗府、试炼塔、竞技场、派遣、完整图鉴剧情 | `locked` | 依赖战斗或未完成的特色玩法切片 |
| 灵兽与灵骑 | `locked` | 实体成长、装备、休养和 BattleSnapshot 规则完成后再接入 |
| 宗门、师徒、队伍、市场、生产委托、灵叶和完整世界事件 | `planned` | 社交/经济/活动域的状态机、锁定和恢复演练完成 |
| 合道至渡劫、三界正式区域、赛季和终局 | `open`（仅合道/渡劫非战斗状态机） | 三界正式区域、终局战斗、飞升/留界结局仍按后续切片开放；不得跳过境界和试炼前置 |
| Web 写操作、外部支付正式接入 | `locked` | 先完成权限、审计、备份恢复和 billing adapter 合同 |

## 4. 开发顺序

开发按可独立验收的垂直切片推进，不按 `content-v0.1`、`content-v0.2` 逐个版本搬运：

1. 稳定当前已开放切片的迁移、回放、并发和适配器契约。
2. 完成社交、经济、活动和常驻经营的基础闭环，补齐队伍与战斗前置状态。
3. 实现服务端自动回合战斗：先训练夹具和单人 PVE，再多人 PVE，最后 1v1/多方 PvP。
4. 按金丹、元婴、化神、炼虚、合道、渡劫切片扩展高阶境界和三界内容。

每个新切片必须同时提交规则、application DTO、迁移、适配器、测试、观测字段、关闭新建
语义、历史会话处理和回滚步骤；只有满足[首版验收门槛](content-development.md#22-首版验收门槛)
才可把状态从 `contract`/`locked` 改为 `open`。

## 5. 文档维护规则

- 改玩法边界、境界或跨域依赖：先改 `content-development.md`。
- 改实体、状态机或用例契约：改对应域的 `model.md`、`workflow.md` 或 `use-cases.md`。
- 改当前实现状态：只改本文，并在对应域 README 保留链接，不复制整张状态表。
- 改历史发布参数：只改相应 `content-v*.md`，同时说明 `content_version` 和 `rule_version`。
- 代码、命令处理器和测试不得自行创建与文档冲突的第二套规则。
