# 当前开发状态

本文只回答一个问题：**当前分支哪些能力已经可以运行，哪些仍然只是规则或内容合同**。
它不是玩法规则的第二份定义；规则、数值、稳定键和完整路线仍以[完整内容开发总表](content-development.md)
及各域的 `model.md`、`workflow.md`、`use-cases.md` 为准。

## 1. 状态定义

| 状态 | 含义 | 是否允许新增运行时入口 |
|:--|:--|:--:|
| `open` | 已有 application 用例、持久化、幂等和适配器测试，可供玩家使用 | 是 |
| `partial` | 已有可玩的局部流程，但声明的内容奖励、来源或验收仍未闭合 | 否；只补齐既有合同，不扩大玩法面 |
| `contract` | 已有完整规则、稳定键和测试夹具，但尚未接入运行时 | 否 |
| `locked` | 已登记内容或接口，前置条件尚未满足，统一返回内容未开放 | 否 |
| `planned` | 已列入开发路线，尚未完成规则闭合 | 否 |

`content-v0.1` 至 `content-v0.6` 是发布快照，不代表当前状态，也不代表代码开发顺序。
快照中的 `open` 只表示该版本发布时计划开放；本文件中的 `open` 才表示当前代码已经接入。

## 6. 文档维护规则

- 改玩法边界、境界或跨域依赖：先改 `content-development.md`。
- 改实体、状态机或用例契约：改对应域的 `model.md`、`workflow.md` 或 `use-cases.md`。
- 改当前实现状态：只改本文，并在对应域 README 保留链接，不复制整张状态表。
- 改玩法参数：直接更新 `content-development.md`、对应域文档和现行 JSON，并同步更新消费测试；未发布内容不维护旧格式、旧字段或兼容迁移。
- 代码、命令处理器和测试不得自行创建与文档冲突的第二套规则。
