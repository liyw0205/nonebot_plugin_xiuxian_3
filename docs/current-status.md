# 运行能力状态判定

玩家当前可用的功能范围见[当前可用能力](availability.md)，实际命令与流程见[玩家使用指南](usage.md)。
文档中的设计项、内容记录、测试夹具和历史快照都不单独构成公开能力；最终以正式版本的公开入口和运行时校验为准。

## 状态定义

维护内容或实现说明时，使用以下状态描述证据边界：

| 状态 | 含义 |
|:--|:--|
| `open` | 玩家公开入口、准入、来源、实际消费者和持久化结果已接通并按适用范围验证 |
| `partial` | 只接通明确列出的部分流程，未覆盖部分仍不可据此推断为可用 |
| `contract` | 规则和数据合同已定义，但尚无可执行的玩家入口 |
| `locked` | 有意关闭或前置条件未满足；入口应拒绝新建且不得扣除资产 |
| `planned` | 规则或依赖仍未闭合，不能据此开放会话或结算 |

状态描述必须与范围、版本和证据相邻。测试通过只证明被测合同；模拟平台、测试凭证、配置记录和历史通过结果不能替代当前发布或真实平台验收。

## 更新边界

- 玩家可用功能的变更同步更新[当前可用能力](availability.md)和对应的命令流程。
- 内容键、公开来源、跨文件引用和真实消费者按[数据内容合同](content-data-contract.md)维护。
- 事务、快照、幂等、重试、恢复和数据库变化按[通用行为合同](content-development-contract.md)维护。
- 任务队列、分支运行状态、提交/CI 记录和临时环境验收属于工作记录，不写入发布文档；版本发布记录只保留在正式变更日志及对应发布资产中。
