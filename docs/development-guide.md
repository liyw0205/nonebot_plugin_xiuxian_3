## 2. 开始一项工作

1. 读 current 的唯一队列，选择最高优先级且依赖满足的任务；先复用已有入口、代码和验收证据。
2. 阅读总表、数据合同与对应领域合同。可以为 `partial/contract/locked/planned` 补合同/实现前置，
   但未满足开放门槛时仍拒绝新建，不扣资产；不能把“未开放”理解成永远不能开发。
3. 在 current 同一行登记缺口/复现、合同引用、目标、依赖、文件所有权和受影响验收范围。
4. 先补缺少的规则或 JSON 字段及引用，再接通通用解释、application、领域 repository 与事务。
   没有规则依据或设计授权时列具体问题和解除条件。当前 M7 用户已授权 xiu3 设计缺失本地来源、
   配方和参数：保守复用既有阶梯，记录选择后落数据与消费，不等待用户逐个给数值；未来锁定功能不自动开放。
5. 文本、按钮、QQ、OneBot、Web 共用 application；适配器只归一化事件和呈现，不复制结算。
6. 用[测试策略](testing.md)选择快测；记录 passed/failed/skipped 和未覆盖项，完成后更新同一队列行。
   只有阶段验收才启动长测，无相关改动/失败/未解疑点时不重复验证。

### 3.3 有限队列与重复开发防线

每个发布里程碑只做一次全产品范围对照，把实际缺项收束为有证据、有依赖、有退出条件的有限表。
从总表全部功能域确认已有玩家链与合同缺项，已完成项复用，不靠历史行号、Python 子包
或孤立 JSON 推断待办；只在新证据改变队列判断时做针对性复核，不每轮重新全域扫描。

按已登记目标、依赖与玩家影响推进；修复可复现回归优先。取消原十条冷却/目录轮转硬门槛，
不为了轮转而重复审计或拖延完整范围交付。一个任务完成只关闭该行，不把小修复当本轮全部必需工作或完整游戏完成。
只有新的可复现缺陷、现行合同缺项或明确需求才能扩充队列，并说明为何属于冻结范围。
2026-10-10 M5、M6 及分类帮助/悬赏切片已完成；当前 M7 按 current 的一次分域盘点冻结清单，
逐项证明定义、引用、公开来源和实际消费。完成该有限清单后交付，不循环追加无证据缺陷。

同一事务只允许一个主线改动者。只有明确授权且存在独立文件边界时使用子代理，
先登记只读/可写范围和文件所有权；不同时改同一仓储/夹具，也不重复启动同一审计或长测试。
主线统一合并并验证受影响边界；协作本身不触发全量复验。

## 4. 交付合同

既有玩法合同完整保留，每项涉及的合同须明确：

- 入口、权限、用户文案、消息投递与降级；投递失败不回滚业务事务。
- 实体、状态机、不变量、DTO、错误码与锁；前置、成本、产出、配额/冷却、失败/取消/过期。
- application owner、UoW、operation 输入冲突与幂等、资产流水、唯一约束、并发和异常回滚。
- JSON 实际消费、稳定键/跨内容引用、可达来源、随机因子/候选权重、开始快照与冻结实际结果。
- 数据库结构、备份恢复、关闭新建、已有会话处理与回滚；不删除用户数据。
- 受影响领域/应用/适配器/并发/重放/故障测试，以及 request/operation、角色、功能、结果、耗时和错误观测。

自动战斗由服务端按开始快照选择行动、技能和目标；客户端不得提交攻击、防御、技能、
目标、伤害或结算。PvE 单人/多人和 PvP 个人/组队分别满足自己的前置与恢复/回放合同。
训练傀儡与直接切磋仍只读观战。未接通或未定义的效果不能配置成可用。

JSON 只放随内容记录变化且需要内容包调整的名称、描述、数值和奖励等字段。
命令格式、固定错误提示和少量固定引导语留在领域代码，不参与规则判断、不进入业务快照，
不为了“内容化”给每条记录复制无业务用途的短句。

## 5. 共享工具与数据边界

复用 `xiuxian/utils/` 中的 JSON 缓存/严格解码、SQLite 初始化、资产/角色状态、
operation 重放和确定性随机工具；不复制 SQL、奖励表、数值转换或哈希抽取循环。
JSON 缓存按文件身份/变更时间失效，返回独立副本；坏 JSON、重复键、缺字段和坏引用明确失败，
不得吞错、补静默默认值或返回空内容。配置变化必须由实际消费测试证明。

`persistence/` 管理 schema、迁移、事务和通用存储，领域 repository 管理本域状态与结算；
`utils/` 不放境界/道途/任务/奖励/装备等领域专用规则。
项目预发布可直接重构 schema 与隔离测试库，不新增无用途的版本字段或旧格式兼容分支。
测试不得读取真实运行库；清空开发数据须备份并明确指定目标，禁止自动删用户目录/数据库。

缓存清理只处理当前任务确认归属的产物，保护 `/tmp/codex-daemon-*`、活跃 agent 目录、
IPC、socket 和 lock；不得按目录名/体积或通配符清空 `/tmp`。
具体边界见[运行规范](operations.md#6-开发产物与缓存清理)。

## 6. 验证与完成

统一使用 `/root/myenv/bin/python`。只改文档：文档链接测试与 `git diff --check`；
代码/内容改动：复现测试、本域与受影响调用方/共享边界，按需编译、内容/引用检查。
全量约两小时的回归和完整成长长链只在发布阶段、重大共享变化或不能由聚焦测试解释的回归时运行，
每份长测只有一个运行者；全量已有长链覆盖就复用，不重复跑。
QQ/OneBot 共用 router/application/repository，共享业务完整链仅跑一次；两端保留实际事件、
身份、权限、去重和投递差异的短合同。适配器上游修复只触发受影响接入边界，
除非实际改变共享业务或仍有未解跨域风险，否则不重复游戏成长/仿真长链。

2026-10-10 M5 旧双平台树全量/成长已实际通过，最终树经等价去重与短合同补验；该证据是历史基线。
当前 M7 使用内容引用校验与受影响公开取得/消费/失败恢复短测，OneBot 代表共享链一次，QQ 仅受影响合同。
没有明确新覆盖需求不重跑完整成长、全量或仿真；不压测，不并行长测，不部署。
纯文档或保持夹具/命令/行为断言的等价测试去重可以复用未变业务基线的全量证据；
记录测试树差异并核对结构、收集和受影响短合同，不为平台字符串少执行一遍而重跑长测。
B1 缺规则/来源、B2/B3 外部条件只阻断完整产品/正式发布，不阻断已有公开能力的本地验收。
安装/启动/备份恢复证据按适用范围复用；真实失败最小修复，不得 skip/ignore、删行为断言或降阈值。

用户已授权本轮审查相关 code/test/docs/AGENTS、提交与普通 push 到 `origin/main`。
验收实际通过、审查完成且 commit/push 成功后才可结束本轮 goal；不发版、不 force，
不 stage 用户数据、运行库、密钥、日志或缓存。结果文档更新只补文档检查，业务基线不变不重跑长测。

发布还需安装/启动、内容/来源、迁移/恢复与相应真实 QQ/OneBot 验收。
模拟 adapter、测试凭证和本地周赛只证明其合同边界；真实平台、正式支付、跨服与投产条件单列，
不自行开放。skip、文档通过、局部通过或历史记录不能冒充完整验收。
触发与命令只由[测试策略](testing.md)维护，其他文档不再复制全量命令门槛。
