# 开发文档总入口

本文只负责回答“开发时先读什么、改哪份文档、怎样算完成”。它不复制玩法数值、
境界阈值或当前运行状态；这些内容分别由总表、领域文档和状态页负责。

## 一、四个问题，四个入口

| 要回答的问题 | 唯一入口 | 说明 |
|:--|:--|:--|
| 应该开发什么 | [完整内容开发总表](content-development.md) | 全部境界、功能域、稳定键、发布边界和完整路线 |
| 静态内容和玩法数值放哪里 | [数据内容开发合同](content-data-contract.md) | JSON 唯一来源、配置维度、随机与引用校验 |
| 当前已经开发什么 | [当前开发状态](current-status.md) | 运行时开放、部分完成、合同、锁定和下一切片 |
| 先开发哪一条 | [实施计划](implementation-plan.md) | 依赖图、垂直切片、验收和回滚 |
| 一个领域怎么实现 | 对应领域的 `README.md`、`model.md`、`workflow.md`、`use-cases.md` | 实体、状态机、应用契约和领域验收 |

不要从旧方案、命令处理器或顶层兼容页补全规则。文档中的版本号只用于方案对照，不是运行时
配置或开发顺序；同一领域的当前规则应合并在领域文档中，不按版本快照逐个搬运。

### 2.1 当前配置与运行状态的边界

运行时内容包和开发状态是两条不同的轴，不能互相替代：

| 需要判断的事实 | 读取位置 | 判断方式 |
|:--|:--|:--|
| 稳定键、境界和完整功能范围 | `content-development.md` | 以总表的定义、依赖和首版边界为准 |
| 静态配置是否存在、引用是否闭合 | `data/内容清单.json`、`static-data-inventory.md` | 只读加载配置；`active/open` 表示已注册，不代表玩家可执行 |
| 当前命令或 Web 入口是否可用 | `current-status.md` | 只有 `open` 能新增玩家入口；`partial` 不能把测试夹具当成入口 |
| 本条切片的实体、流程和结算 | 对应域的 `README.md`、`model.md`、`workflow.md`、`use-cases.md` | 领域文档覆盖实现细节，不在命令层补规则 |

因此，新增内容时先登记稳定键，再决定是否进入静态包，最后由当前状态页决定是否接入
运行时。配置包可以提前登记未来境界或天劫敌人，但在状态页为 `locked`、`contract` 或
`partial` 时，命令、按钮和 Web 写入口必须拒绝创建会话且不得扣除资产。

## 三、开始一条开发切片

按以下顺序处理，每一步都要能在提交中找到对应文件：

1. 读 `current-status.md`，确认功能不是 `partial`、`locked`、`contract` 或 `planned`，并记录现有前置。
2. 读 `content-development.md` 和 `content-data-contract.md`，确定稳定键、配置结构、适用因子、成本、产出与随机合同。
3. 进入对应领域目录，阅读 `README.md`、`model.md`、`workflow.md`、`use-cases.md`。
4. 先补 JSON 业务配置和内容校验测试；同一个内容/数值不得另留 Python 字典、`if/elif` 表或静默默认值。
5. 再实现通用规则解释、application 用例、领域 repository 和 operation ledger；数据库保存运行态与结算所需的业务快照，不取代静态配置。通用 JSON 缓存和 SQLite 连接初始化放在 `xiuxian/utils/`；schema、事务和迁移归 `xiuxian/persistence/`。
6. 接入统一 application 用例；文本、按钮、QQ、OneBot 和 Web 不能各写一套结算逻辑。
7. 按[消息与文案规范](messaging-copywriting.md)写玩家文案，再按适配器能力发送：QQ 优先 Markdown，OneBot 支持普通消息/合并转发；降级不能回滚业务事务。
8. 补齐配置变更测试、引用闭合、重复请求、并发冲突、随机回放、超时/取消、异常回滚、恢复和双适配器验收。
9. 更新当前状态和对应领域文档，最后执行本页的文档与工程门槛。

### 3.1 子代理协作

按任务的独立性、风险和并行收益决定是否使用子代理，不要求每条切片都拆分；子代理不能替代主线实现和验收。
默认先安排只读审阅，
分别核对内容合同、共享工具复用点、真实 PvE/PvP 结算边界、适配器入口、恢复和测试缺口；
审阅结论必须带文件、函数、事务边界和风险，不直接改动主线工作树。需要并行编码时必须按
文件/模块明确所有权，禁止多个代理同时修改同一仓储或测试夹具；主线代理负责统一合并、解决
边界冲突、补齐端到端代码和测试，并重新运行全部门槛。每条切片在 `implementation-plan.md`
记录采用或不采用并行协作的原因；有子代理时，记录其职责、只读/可写范围、结论和未覆盖项；玩家可见文案、运行时版本标识和
旧格式
兼容分支不由子代理自行添加。

## 四、切片交付清单

每条垂直切片必须同时说明：

- 入口、权限、适配器降级和用户可见文案。
- 实体字段、不变量、状态机、错误码和并发锁。
- 前置、成本、产出、随机池、冷却/配额、失败/取消/过期。
- application DTO、Unit of Work、`operation_id` 幂等和不同输入冲突。
- 迁移、唯一约束、资产流水、备份恢复和关闭新建语义。
- 稳定键、跨内容引用闭合和回滚步骤；文档方案版本号不得变成 Python 常量或 JSON 运行字段。
- JSON 的实际消费入口、所有随机因子、候选权重、奖励池和冻结快照；确认没有重复 Python 内容表、静默默认值或按境界/道途分支。
- 领域、应用、适配器、并发、回放和故障测试。
- `request_id`、`operation_id`、角色、功能、结果、耗时和错误观测字段；不记录无业务用途的内容/规则版本号。

战斗切片还必须遵守自动回合合同：服务端依据开始快照自动选择行动、技能和目标；客户端
不得提交攻击、防御、技能、目标、伤害或结算结果。PVE 支持单人和多人协作，PvP 支持
`1v1` 与 `N v M`，未满足角色、属性、装备、技能、队伍、恢复和回放前置时只能维护合同，
不得创建运行时会话。

## 五、状态怎么判定

| 状态 | 含义 | 开发约束 |
|:--|:--|:--|
| `open` | 有完整用例、持久化、幂等和适配器测试，可供玩家使用 | 可以新增入口 |
| `partial` | 有部分状态机或生产者，但玩家路径尚未闭合 | 不能新增为玩家入口 |
| `contract` | 规则、稳定键和夹具齐全，尚未接入运行时 | 只能补基础设施和契约测试 |
| `locked` | 已登记但前置或依赖未满足 | 统一返回未开放，不扣资源 |
| `planned` | 仅列入路线，规则尚未闭合 | 不创建会话或资产结果 |

是否开放必须以 `current-status.md` 为准；历史方案中的状态不构成运行时入口。

## 六、共享工具与数据访问

`nonebot_plugin_xiuxian_3/xiuxian/utils/` 只放跨领域、无业务含义的重复工具，例如：

- `json_cache.py`：只读 JSON 加载缓存。按文件身份和变更时间失效，每次返回独立副本；重复 JSON 对象键、解析失败和文件缺失必须明确报错。
- `database.py`：SQLite 连接统一初始化，包括 busy timeout、WAL、同步等级和外键开关。
- `assets.py`：统一校验灵石和背包物品的增减、序列化及组合结算；领域代码只负责额外的修为、声望等专属数值。
- `player.py`：统一读取玩家行和数值字段，供角色信息、状态展示和战斗快照共用；共享状态与奖励入口组合提交资产、数值和声望，`change_player_state_actual` 返回封顶或资源上限处理后的真实差值，领域提供已校验或冻结的增量与上限，不重复编写资产或声望 SQL。
- `randomness.py`：提供基于种子的确定性加权选择和正权重校验；各领域传入已校验的候选与权重，不另写哈希抽取循环。

境界、道途、任务、奖励、装备和领域专用字段解析不属于 `utils`，应留在对应领域模块。加载器
不能吞掉错误、跳过坏记录、补静默默认值或把 JSON 解析失败转换成空内容。修改配置后，运行时
消费路径必须实际读取新值，并由测试证明行为随配置变化。

`persistence/` 管理数据库 schema、事务、迁移和通用存储协议；具体领域 repository 留在对应领域。
项目尚未正式发布，可以直接重构 schema 和测试数据库，不需要维持旧表结构。清理测试库应使用临时
目录或明确指定的测试数据库；任何工具都不得自动删除用户配置的数据目录或数据库文件。清空开发
数据前先备份，并由开发者明确指定目标文件。

## 七、提交前验证

在修改玩法、内容或本目录入口后，至少执行：

```bash
$HOME/myenv/bin/python -m pytest -q
$HOME/myenv/bin/python -m pytest -q test/test_documentation.py
$HOME/myenv/bin/python -m compileall -q nonebot_plugin_xiuxian_3
find data -name '*.json' -print0 | xargs -0 -n1 $HOME/myenv/bin/python -m json.tool >/dev/null
git diff --check
```

文档改动还要检查：入口链接没有断链、总表/状态页/领域 README 的职责没有重复、方案版本号
没有被写成当前运行状态。一个提交尽量只包含一条可回滚的垂直切片或一个基础设施能力。

## 八、旧文档入口

`docs/foundation-*.md`、`docs/gameplay-*.md` 和 `docs/extension-*.md` 为旧链接保留的
概览页。它们不再定义规则、开放状态或开发顺序；实现前请从[文档索引](index.md)进入
对应目录的 README，并以领域文档作为当前合同。
