# 扩展：数据与内容配置

> **兼容概览，非权威。** 开发时先读[开发文档总入口](development-guide.md)，再进入[数据内容域](extensions/content/)；当前状态以[当前开发状态](current-status.md)为准。

内容范围、首版开关和完整境界/功能路线以[完整内容开发总表](content-development.md)为准；
本文只说明运行时数据格式、加载校验和发布边界。

## 1. 两类数据

### 规则数据

规则数据决定公式、状态机、资源上限、概率、冷却和权限。规则变更必须有 `rule_version`、生效时间、变更人和回滚方式。

### 内容数据

内容数据包括地点、敌人、技能、功法、物品、配方、任务、事件、奖励池和文本。内容变更使用 `content_version`，不应该偷偷改变已经结算的历史结果。

## 2. 内容文件

建议使用版本化 JSON/YAML 或数据库种子，目录按领域拆分，路径是运行时约定而不是版本目录：

```text
data/
  内容清单.json
  境界/境界.json
  装备/法器.json
  道具/材料.json
  生产/配方.json
  ...
```

每个文件包含 schema 版本、内容版本、更新时间、`kind` 和 `records`。每条记录
使用统一的 `key` 字段；稳定键使用字符串，不使用上游 ID 区间。

## 3. 加载校验

启动或发布前检查：

- schema 合法。
- 稳定键不重复。
- 引用的技能、物品、地点、配方和奖励池存在。
- 数值在允许范围。
- 权重非负且总和满足规则。
- 境界、道途、阵营和地点条件可解析。
- 文案变量与参数声明一致。
- 禁止执行任意代码、模板表达式或路径操作。

## 4. 数据库边界

数据库保存玩家状态、操作流水、会话、锁定资产、任务进度、内容版本和审计。内容定义可以导入数据库缓存，但原始内容源必须可追溯。

应用层不依赖表名。迁移使用单调版本、事务和重复执行保护。

## 5. 历史结算

战斗、突破、生产、探索、交易和奖励保存输入快照、公式版本、内容版本和输出。管理员修改当前规则不能改变历史结果。

## 6. 迁移

迁移顺序：增加结构 -> 回填 -> 校验 -> 切换读路径 -> 清理旧结构。每次迁移提供：

- 空库测试。
- 已有数据测试。
- 重复执行测试。
- 失败回滚测试。
- 计数和抽样校验。
- 恢复前备份。

修仙 3 不默认迁移上游玩家数据。未来如需迁移，必须单独设计字段映射、丢失项、补偿规则、dry-run 和回滚。

## 7. 内容发布

内容发布和代码发布分离但使用同一版本记录。发布前先在临时数据根加载和模拟结算，再更新运行时内容版本。

## 8. 管理员编辑

Web 编辑只能修改白名单字段，并生成草稿、校验、预览、发布和回滚记录。高风险概率、奖励、经济和权限数据需要二次确认。

## 9. 首版范围

首版完成内容 schema、加载校验、规则版本、内容版本、基础迁移和奖励池快照。在线内容编辑和热加载后置。

## 10. 实现合同

### 10.1 内容包结构

```json
{
  "schema": "xiuxian.content",
  "schema_version": 1,
  "content_version": "content-2026-01",
  "rule_version": "rules-v1",
  "generated_at": "2026-01-01T00:00:00Z",
  "kind": "item",
  "records": [{"key": "item.weapon.wood_sword", "name": "木纹剑"}]
}
```

内容包加载为不可变发布对象。运行时只激活通过校验的版本，旧版本保留到所有引用和历史结算不再需要后再清理。

### 10.2 校验阶段

1. 解析 JSON/YAML 和 schema。
2. 检查稳定键、版本和类型。
3. 建立引用图，检查缺失、循环和不允许的跨域引用。
4. 检查数值边界、权重、时间和权限。
5. 使用 fake 角色执行公式、状态机和奖励模拟。
6. 生成校验报告和内容摘要。

任何一项失败都不能发布；警告项必须有负责人和过期时间。

### 10.3 内容与迁移用例

- `validate_content_bundle`：输入内容目录和目标版本，输出校验报告，不修改运行数据。
- `preview_content_release`：输入通过校验的内容包，输出引用差异、数值差异和影响范围。
- `publish_content_release`：输入发布确认和 `operation_id`，激活内容版本并写审计。
- `run_migration`：输入迁移版本、数据库范围和 `operation_id`，输出迁移结果、校验摘要和回滚点。
- `rollback_content_release`：输入旧版本和确认令牌，恢复可用版本，不修改历史结算。

错误码：`CONTENT_SCHEMA_INVALID`、`CONTENT_KEY_DUPLICATE`、`CONTENT_REFERENCE_MISSING`、`CONTENT_VALUE_INVALID`、`CONTENT_VERSION_ACTIVE`、`MIGRATION_PRECHECK_FAILED`、`MIGRATION_FAILED`、`RELEASE_CONFIRMATION_REQUIRED`。

### 10.4 数据库迁移合同

迁移脚本声明版本、依赖、预检查、升级步骤、回滚策略和校验查询。迁移运行记录保存开始/结束时间、数据库摘要、操作者、结果和错误。

迁移必须支持：空库、当前库、重复运行、中途失败恢复、备份恢复和只读兼容窗口。

### 10.5 规则发布

规则发布前生成 `RuleRelease`：规则版本、公式摘要、参数差异、影响的玩法、预计经济影响、审批人和生效时间。历史 operation 永远引用旧规则版本。

### 10.6 验收样例

1. 缺失物品/地点/技能引用时内容包拒绝加载。
2. 重复内容键和非法负权重不能发布。
3. 同一内容包重复加载不会产生重复记录或重复奖励。
4. 迁移中途失败后可从备份恢复并重新执行。
5. 规则发布后，新操作读取新版本，旧结算仍读取原版本。
