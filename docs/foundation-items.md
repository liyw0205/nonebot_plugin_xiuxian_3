# 基础：资源与物品

> **兼容概览，非权威。** 开发时先读[开发文档总入口](development-guide.md)，再进入[资源与物品域](foundation/items/)；当前状态以[当前开发状态](current-status.md)为准。

## 1. 核心资源

| 资源 | 来源 | 消耗 | 约束 |
|:--|:--|:--|:--|
| 修为 | 修炼、探索、任务、事件 | 境界层数和突破 | 不直接兑换灵石 |
| 灵石 | 任务、生产、交易、服务、常驻经营 | 市场、配方、委托、居所/设施维护 | 余额不可为负 |
| 体力 | 周期恢复、少量奖励 | 探索、战斗、高风险行动 | 有上限和冷却 |
| 精力 | 周期恢复 | 生产、生活和委托 | 与战斗体力分开 |
| 气血 | 战斗、药物、休息 | 战斗损伤 | 不能用普通查询修改 |
| 灵力 | 施法、恢复、药物 | 技能和法器 | 战斗快照结算 |
| 材料 | 采集、战斗、生产、交易、灵田 | 制造、任务和公共建设 | 有品阶、绑定和来源 |
| 声望 | 宗门、城市、阵营、事件和常驻经营 | 资格、兑换、关系和设施 | 分阵营、分地区、分轮次 |
| 服务信誉 | 委托、运输和常驻服务 | 服务等级、押金和订单槽 | 0–100，不可交易 |

污染、血脉、道基质量、战意、契约和化形稳定度属于道途状态资源，不能当作普通货币处理。

## 2. 物品分类

修仙 3 采用内容标签而不是固定的旧 ID 区间：

- 功法：提供修炼方向和常驻效果。
- 辅修配方：提供生产动作和品质规则。
- 技能：战斗或探索中的主动/被动效果。
- 法器：武器、护具、机关和本命法器。
- 丹药：恢复、准备、临时状态和特殊剧情道具。
- 材料：药材、矿材、阵材、灵植、部件和通用材料。
- 特殊物品：钥匙、凭证、契约、任务物品和世界事件道具。
- 奖励包：固定奖励或版本化随机奖励。
- 称号：成就展示和有限的非核心效果。

宠物、傀儡和机关如果有独立成长，应使用实体实例，不作为普通堆叠物品。

## 3. 品阶

首版建议使用统一品阶：凡、灵、宝、道、天、仙、神、禁忌。品阶只表示内容质量区间，不直接绑定某一境界或旧项目等级。

每件物品还应有：

- `item_key`：稳定内容键，不使用连续数字推断语义。
- `item_type`：功法、技能、法器、丹药、材料等。
- `quality`：品质或品阶。
- `bind_type`：不绑定、角色绑定、宗门绑定、事件绑定。
- `stack_limit`：堆叠上限。
- `durability`：耐久和维修规则。
- `rule_version`：效果与结算规则版本。
- `content_version`：内容定义版本。

## 4. 功法和技能

功法可影响修炼、属性、道途适配和辅修学习，但不能同时无条件覆盖所有方向。

技能必须声明：

- 目标和范围。
- 资源消耗。
- 冷却和行动成本。
- 命中、控制或状态概率。
- 伤害/治疗/护盾基础值。
- 与属性和道途的缩放方式。
- 失败结果和日志文本。

技能效果使用效果类型和参数结构，不把任意 Python 代码或字符串表达式直接存进内容文件。

## 5. 装备和机关

装备槽至少区分武器/法器、防具、饰品、本命法器和机关槽。器修可以拥有更多机关互动，但不能突破全局操控上限。

装备状态包括：耐久、强化、改造槽、绑定、来源、当前使用者和效果快照。强化和改造必须有失败、回滚和材料消耗规则。

## 6. 丹药

丹药分为：恢复、修炼辅助、突破准备、战斗临时、污染/血脉处理和剧情特殊。

永久属性丹药要设置总量上限、使用间隔或递减收益，避免生活生产变成无限堆属性。

## 7. 奖励包和随机内容

奖励包声明：

- 固定奖励。
- 随机池和权重。
- 保底规则。
- 适用场景和有效期。
- 规则版本。
- 是否绑定。

开奖时保存奖励包快照和实际结果，不能只保存最终物品数量。

## 8. 背包不变量

- 数量不能为负。
- 叠加规则和容量在同一事务检查。
- 使用物品和消耗物品必须幂等。
- 唯一物品不能被重复生成。
- 交易、生产和战斗奖励先锁定再结算。
- 删除或拆分物品保留来源和操作记录。

## 9. 内容来源

物品、技能和配方内容优先使用版本化 JSON/YAML 或数据库种子。内容加载时执行 schema 校验、重复键检查、引用检查、数值范围检查和规则版本检查。

## 10. 实现合同

### 10.1 内容定义

每个物品定义至少包含：

```json
{
  "item_key": "item.armor.cotton_robe",
  "item_type": "armor",
  "quality": "common",
  "bind_type": "unbound",
  "stack_limit": 1,
  "effects": [],
  "requirements": [],
  "rule_version": "items-v1",
  "content_version": "content-2026-01"
}
```

`effects` 只能引用白名单效果类型；内容文件不能执行代码、SQL、模板或文件路径。

### 10.2 物品实例

唯一物品使用 `ItemInstance`，保存：`instance_id`、`item_key`、持有者、绑定状态、数量、耐久、强化/改造状态、来源 operation、创建时间和规则版本。

堆叠物品使用 `InventoryStack`，唯一键为角色、物品键、绑定类型和必要的品质维度。合并堆叠前必须检查容量和绑定一致性。

### 10.3 用例契约

| 用例 | 预检查 | 成功写入 | 失败码 |
|:--|:--|:--|:--|
| `grant_item` | 奖励定义存在、数量合法 | 物品/堆叠、流水 | `ITEM_DEF_NOT_FOUND`、`INVENTORY_FULL` |
| `consume_item` | 持有数量足够、状态允许 | 数量扣减、流水 | `ITEM_NOT_OWNED`、`ITEM_BOUND` |
| `equip_item` | 槽位、境界、道途和绑定 | 装备槽、属性快照 | `EQUIP_SLOT_BUSY`、`REQUIREMENT_MISSING` |
| `use_item` | 使用条件、冷却、目标有效 | 状态/资源/物品 | `ITEM_COOLDOWN`、`ITEM_TARGET_INVALID` |
| `repair_item` | 维修材料、装备归属 | 耐久、材料、流水 | `DURABILITY_FULL`、`RESOURCE_INSUFFICIENT` |

所有用例都接收 `operation_id`，奖励、消耗、装备和使用不能分散为多个无幂等写入口。

### 10.4 物品状态机

```text
defined -> granted -> owned -> equipped/locked
owned/equipped -> consumed/destroyed/transferred
locked -> settled/unlocked
```

交易、生产、战斗奖励先进入 `locked` 或待领取状态，再在结算 operation 中转为角色持有。

### 10.5 错误码和失败语义

物品用例统一使用以下错误码：`ITEM_DEF_NOT_FOUND`、`INVENTORY_FULL`、`ITEM_NOT_OWNED`、`ITEM_BOUND`、`EQUIP_SLOT_BUSY`、`REQUIREMENT_MISSING`、`ITEM_COOLDOWN`、`ITEM_TARGET_INVALID`、`DURABILITY_FULL`、`RESOURCE_INSUFFICIENT`、`ITEM_OPERATION_CONFLICT`。

错误发生在预检查阶段时，不扣数量、不改变装备槽、不生成奖励流水。结算阶段失败时，事务整体回滚；如果外部投递已经成功但本地确认失败，进入待处理状态，由恢复任务继续结算，不允许手工重复发放。

### 10.6 随机奖励

开奖输入包括奖励池键、权重版本、保底计数、角色快照和 operation ID；输出保存抽取项、随机结果摘要、保底变化和实际物品流水。重复领取返回原奖励，不重新抽取。

### 10.7 验收样例

1. 背包容量不足时奖励全部拒绝或进入明确待领取状态，不能部分丢失。
2. 同一物品使用 operation 重试只消耗一次并返回同一结果。
3. 绑定物品不能交易或转移给不允许的目标。
4. 物品定义下线不影响已有实例读取和历史结算。
5. 随机奖励保存池版本和实际结果，规则更新不改变已开奖物品。
