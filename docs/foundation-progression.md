# 基础：境界与突破

## 1. 公共境界

所有正式修行者共享同一套公共境界，道途只改变属性偏重、技能标签和资源循环，不另建互相无法比较的等级树。

| 序号 | 境界 | 层数与段位 | 核心变化 |
|:--:|:--|:--|:--|
| 0 | 凡人 | 未入道 | 生活、采集、基础任务 |
| 1 | 感气 | L1–L3 入门；L4–L6 稳固；L7–L9 圆满；L10 混元 | 感知灵气，建立真气 |
| 2 | 聚气 | L1–L3 入门；L4–L6 稳固；L7–L9 圆满；L10 混元 | 真气成流，稳定使用术法 |
| 3 | 筑基 | L1–L3 入门；L4–L6 稳固；L7–L9 圆满；L10 混元 | 形成道基，确定主修根基 |
| 4 | 金丹 | L1–L3 入门；L4–L6 稳固；L7–L9 圆满；L10 混元 | 灵力凝核，形成战斗体系 |
| 5 | 元婴 | L1–L3 入门；L4–L6 稳固；L7–L9 圆满；L10 混元 | 神魂与道基分化 |
| 6 | 化神 | L1–L3 入门；L4–L6 稳固；L7–L9 圆满；L10 混元 | 神意外显，形成领域雏形 |
| 7 | 炼虚 | L1–L3 入门；L4–L6 稳固；L7–L9 圆满；L10 混元 | 接触界壁和虚实变化 |
| 8 | 合道 | L1–L3 入门；L4–L6 稳固；L7–L9 圆满；L10 混元 | 与大道形成稳定契合 |
| 9 | 渡劫 | L1–L3 入门；L4–L6 稳固；L7–L9 圆满；L10 混元 | 验证飞升资格或终局路线 |

首个正式版本建议开放到筑基或金丹；高境界先完成规则和数据结构，不在没有内容支撑时开放。

## 2. 修为

修为是公共成长资源，不直接兑换灵石。修为来源包括：

- 正常修炼和闭关。
- 探索、历练、任务和世界事件。
- 功法、洞天环境和临时状态。
- 特定丹药或神物，但必须受每日上限和经济约束。

修为收益结算保存：角色境界、道途、环境、功法、状态、消耗、规则版本和实际结果。

## 3. 境界十层

每个正式境界有十层。L1–L3 为入门，L4–L6 为稳固，L7–L9 为圆满，L10 为混元；只有 L10 可跨境突破。详细阈值、迁移和持久化字段以 [十层规范](foundation/progression/layers.md) 为准。

各境界 L1–L10 的境内修为阈值与跨境总修为门槛只在
[十层规范](foundation/progression/layers.md)维护。旧三段阶段、旧 1,000/8,000/50,000/240,000
阈值和“圆满即可跨境”都不是当前规则。

## 4. 突破流程

```text
查看突破条件
  -> 准备材料 / 状态 / 功法 / 辅修
  -> 创建突破 operation
  -> 固定 StatSnapshot 和规则版本
  -> 生成成功或失败结果
  -> 应用境界、修为、状态和奖励变化
  -> 写入流水和可回放记录
```

准备度可以来自：

- 当前境界层数与派生段位。
- 道基质量。
- 功法和道途匹配度。
- 丹药、阵法和环境。
- 当前气血、灵力、污染、血脉和虚弱状态。
- 师徒、宗门或世界事件提供的有限帮助。

## 5. 成功率

策划表达式：

```text
突破成功率 = 基准率 + 准备度 × 0.25 + 道基质量 × 0.20 - 风险修正
```

运行时使用万分比整数。所有加成必须明确归属乘区，不能让同一丹药同时重复计入准备度、道基质量和最终概率。

概率要设置最低成功保障或失败保护，避免玩家因连续失败永久落后。保护材料可以降低损失，但不能把所有突破变成无风险按钮。

## 6. 失败状态

突破失败不直接删除角色成长，按境界设置可理解的状态：

- 虚弱：一段时间内限制高风险行动。
- 道基震荡：降低修炼效率，完成恢复任务后解除。
- 心魔：生成一次事件或选择题，处理方式影响污染和准备度。
- 天劫残痕：影响下一次突破，但可以通过生产、宗门或洞天内容处理。

失败产生状态、消耗和补偿都必须写入 operation 结果。

## 7. 渡劫与终局

渡劫不是普通突破的放大版。它应由角色历史、道途、阵营、关系、世界事件和道果选择共同决定。首版只预留数据结构，不开放完整飞升和轮回系统。

终局路线至少预留：飞升、留界、建立道统、转为世界事件角色或开启新篇章。终局不应破坏历史流水和已完成赛季数据。

## 8. 首版范围

实现感气、聚气、筑基前准备、修炼、基础突破、失败保护、虚弱状态和突破快照。金丹以上只完成规则注册和内容占位。

## 9. 实现合同

### 9.1 持久化字段

`Progression` 保存：

| 字段 | 约束 | 说明 |
|:--|:--|:--|
| `player_id` | 唯一外键 | 角色 |
| `realm_key` | 内容键 | `mortal`、`qi_sensing`、`qi_gathering`、`foundation` 等 |
| `realm_layer` | 0–10 | 凡人 0；正式境界当前层数 |
| `realm_cultivation` | 非负整数 | 当前境界内累计修为，决定 L1–L10 阈值 |
| `total_cultivation` | 非负整数 | 历史累计修为 |
| `foundation_quality` | 0-10000 | 道基质量定点值 |
| `breakthrough_state` | 枚举 | `ready`、`preparing`、`exhausted`、`tribulation` |
| `debuff_until` | 可空 UTC | 虚弱或道基震荡结束时间 |
| `rule_version` | 字符串 | 公式版本 |

### 9.2 修炼用例

输入：`player_id`、行动类型、持续时长、环境确认、`operation_id`。

预检查：角色未暂停、没有进行中的互斥会话、体力/精力足够、地点允许修炼、没有突破锁。

成功输出：获得修为、消耗资源、结束时间、公式版本和 `CultivationResult`。

失败错误：`PLAYER_NOT_FOUND`、`PLAYER_SUSPENDED`、`CULTIVATION_BUSY`、`RESOURCE_INSUFFICIENT`、`LOCATION_FORBIDDEN`、`COOLDOWN_ACTIVE`。

修炼结算必须一次性写入资源流水和修为流水；重复 operation 返回同一结果。

### 9.3 突破用例

输入：`player_id`、目标境界、消耗物品、保护选项、`operation_id`。

预检查：当前境界匹配、修为达到门槛、材料足够、气血/灵力达到条件、没有虚弱或进行中的战斗、目标内容已开放。

固定快照：基础属性、道途、功法、辅修、装备、环境、丹药、当前状态、随机池和公式版本。

成功输出：`success`、旧/新境界、旧/新层数、派生段位、消耗、奖励、快照 ID。

失败输出：`failed`、失败原因分类、保留修为、虚弱/震荡状态、实际消耗、下次可尝试时间。

### 9.4 状态机

```text
ready -> preparing -> resolved_success
                  \-> resolved_failure -> recovery -> ready
ready -> tribulation -> resolved_success/resolved_failure
```

只有 `ready` 可以创建突破。`preparing`、`tribulation` 和 `recovery` 期间重复请求返回 `BREAKTHROUGH_BUSY`。

### 9.5 概率与保护

运行时使用万分比：

```text
success_bp = clamp(base_bp + preparation_bp + foundation_bp + support_bp - risk_bp,
                   minimum_bp, maximum_bp)
```

每次失败增加 `pity_count` 或降低下一次失败损失，具体规则绑定 `rule_version`。保底不能跨角色转移，也不能被普通洗点清除。

### 9.6 验收样例

1. 修为不足时突破不扣材料、不改变境界、不创建成功流水。
2. 同一 operation 重试返回相同成功/失败结果和相同随机结果。
3. 失败只应用文档规定的损失，不能出现修为和材料同时多扣。
4. `recovery` 状态期间修炼和再次突破按错误码拒绝。
5. 规则版本更新后，历史突破读取原快照，新突破读取新版本。
