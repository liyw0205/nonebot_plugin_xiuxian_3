# 基础：属性与数值

> **兼容概览，非权威。** 开发时先读[开发文档总入口](development-guide.md)，再进入[属性域](foundation/stats/)；当前状态以[当前开发状态](current-status.md)为准。

## 1. 数值表示

所有影响经济、战斗、突破、排行或生产的数值使用整数或定点整数。策划文档可以用百分比表达，运行时建议统一为万分比：`10000 = 100%`。

每次结算记录：

- 输入角色和装备快照。
- 境界、道途、辅修和世界规则版本。
- 公式版本。
- 随机池版本和随机结果。
- 最终输出与舍入方式。

## 2. 基础属性

| 属性 | 主要作用 | 不应直接决定 |
|:--|:--|:--|
| 体魄 | 气血、近战、负重 | 全部防御和全部恢复 |
| 灵力 | 灵力上限、法术、护盾 | 生产品质 |
| 悟性 | 修炼、学习、生产学习 | 直接提供稳定伤害 |
| 根骨 | 生命成长、突破、负面抗性 | 掉落稀有度 |
| 身法 | 速度、先手、闪避、探索 | 绝对命中/闪避 |
| 气运 | 事件质量、掉落波动 | 稳定战斗倍率 |

道途状态属性：

- 体修：战意、护体、破势。
- 法修：元素倾向、控制强度、施法效率。
- 器修：器械威能、耐久、操控上限。
- 魔修：魔性、侵蚀、欲念、失控抗性。
- 妖修：血脉、妖力、野性、化形稳定度。
- 辅修：熟练度、专精等级、配方理解和生产质量。

## 3. 派生属性

建议初始公式：

```text
气血上限 = 100 + 20 × 境界序号 + 8 × 体魄 + 5 × 根骨
灵力上限 = 60 + 18 × 境界序号 + 10 × 灵力 + 4 × 悟性
物理伤害 = 技能基础值 × (1 + 体魄 / 100) × 道途系数
法术伤害 = 技能基础值 × (1 + 灵力 / 100) × 道途系数
探索效率 = 基础效率 × (1 + 身法 / 200) × 地点系数
生产质量 = 配方基础质量 + 悟性修正 + 熟练度修正 + 材料修正
```

公式里的 `/100` 只表示策划含义，实际代码使用定点计算。

## 4. 加成乘区

推荐分成：

1. 基础值：境界和角色基础属性。
2. 道途值：首要道途和道途状态。
3. 构筑值：功法、技能、装备、辅修。
4. 环境值：地点、洞天、阵法、世界事件。
5. 临时值：药物、战斗状态和短期增益。

同一乘区先相加再相乘，避免大量小数值形成指数增长。固定值和比例值不得混用而不记录来源。

## 5. 初始上限

首轮平衡基线：

- 常驻单项增伤建议不超过 35%。
- 临时叠加后的单项增伤建议不超过 80%。
- 免伤、闪避、控制抵抗设置软上限，不允许稳定达到 100%。
- 暴击、掉落和气运不得成为唯一有效成长。
- 跨境界挑战通过命中、资源、机制和奖励衰减调整，不直接禁止低境界行动。

上限是规则参数，不是前端隐藏逻辑；超出上限时返回可解释的截断或转换结果。

## 6. 评分和比较

排行榜和匹配不能只使用总战力。建议分别提供：

- 境界榜：公共境界和阶段。
- 战斗榜：固定规则下的 PVE/PVP 结果。
- 生产榜：品质、交付、配方和市场贡献。
- 探索榜：探索深度、事件完成和地图发现。
- 宗门榜：建设、贡献、世界事件贡献。

排行快照按轮次生成，避免实时属性变化造成历史排行漂移。

## 7. 随机性

随机必须服务于决策：

- 结果范围可解释。
- 资源投入能改变分布或失败代价。
- 同一 operation 重放同一结果。
- 随机池、权重和保底按版本保存。
- 管理员调整随机池记录旧版本、新版本和生效时间。

禁止用客户端传入的随机结果作为权威输入。

## 8. 数值测试

每个公式至少测试：零值、最小值、最大合法值、边界上限、多个加成叠加、跨境界、负面状态、舍入和规则版本切换。数值测试不能依赖系统时间或真实随机源。

## 9. 实现合同

### 9.1 属性快照

`StatSnapshot` 至少包含：

| 字段 | 说明 |
|:--|:--|
| `snapshot_id` | 唯一快照 ID |
| `player_id` | 角色 |
| `base_stats` | 体魄、灵力、悟性、根骨、身法、气运 |
| `path_stats` | 道途专属状态属性 |
| `derived_stats` | 气血、灵力、伤害、防御、速度等 |
| `source_refs` | 功法、技能、装备、环境和状态来源 |
| `formula_version` | 公式版本 |
| `created_at` | 快照时间 |

快照是不可变记录。装备、状态或规则变化只能生成新快照。

### 9.2 计算接口

统一提供三个纯计算函数：

```text
build_stat_snapshot(player_state, rule_version) -> StatSnapshot
calculate_action(snapshot, action_definition, context) -> ActionPreview
settle_action(preview, random_result) -> ActionResult
```

`ActionPreview` 只读，不扣资源；`settle_action` 由 application 在事务中调用，并把结果写入 operation。

### 9.3 属性计算状态机

```text
dirty -> building -> ready
                  \-> invalid
ready -> invalid
```

角色境界、道途、装备、状态或规则版本变化时标记 `dirty`。`building` 只在内存中构建快照；校验通过后写入不可变 `ready` 快照，引用缺失、数值越界或版本不可用则进入 `invalid`，禁止用于资产结算。

### 9.4 属性用例

- `preview_stats`：输入角色和规则版本，输出派生属性、来源和警告，不写资产。
- `freeze_stats`：输入角色、用途和 `operation_id`，输出不可变快照 ID，供战斗、突破、生产使用。
- `explain_stat`：输入快照 ID 和属性键，输出计算路径和来源明细。

错误码：`STAT_PLAYER_NOT_FOUND`、`STAT_RULE_NOT_FOUND`、`STAT_SOURCE_MISSING`、`STAT_VALUE_OUT_OF_RANGE`、`STAT_SNAPSHOT_INVALID`、`STAT_SNAPSHOT_PURPOSE_INVALID`。

快照生成失败不能自动使用旧快照进行新的资产结算；只读状态查询可以显示最近有效快照并标记过期。

### 9.5 来源追踪

每个派生属性返回数值和来源列表，例如：

```json
{
  "stat": "max_hp",
  "value": 248,
  "sources": [
    {"kind": "realm", "key": "qi_gathering", "value": 40},
    {"kind": "base_stat", "key": "body", "value": 160},
    {"kind": "equipment", "key": "item.armor.cotton_robe", "value": 48}
  ]
}
```

前端展示可以隐藏细节，但诊断和管理员查询必须可还原。

### 9.6 舍入和边界

- 比例计算使用整数除法并在公式末尾统一舍入。
- 中间值不能提前向下取整导致低属性角色收益为零。
- 负数状态先应用到对应乘区，再执行软上限。
- 软上限、硬上限和溢出处理写入规则定义。
- 非法负资源直接返回 `NUMERIC_INVARIANT_VIOLATION`，不自动修正。

### 9.7 验收样例

1. 相同角色状态和规则版本生成相同快照摘要。
2. 更换装备只生成新快照，不修改历史战斗快照。
3. 同一加成在同一乘区只计算一次，并能列出来源。
4. 软上限触发时返回截断原因，不能静默变成 100%。
5. 规则版本切换不改变已经保存的战斗、突破和生产结果。
