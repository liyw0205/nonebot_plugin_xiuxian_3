# 核心玩法：战斗系统

## 1. 目标

战斗服务于道途构筑、探索风险和世界事件。首版先做可解释、可回放的单人 PVE，再扩展多人和 PVP。

## 2. 战斗类型

- 训练战：无资产损失，用于理解技能和构筑。
- 探索战：探索会话中的战斗，影响探索结果。
- PVE：地点敌人、遗迹守卫、世界事件敌对单位。
- 精英/首领：有阶段、机制和贡献奖励。
- PVP：切磋、竞技和赛季匹配，默认隔离新玩家。
- 阵营战：宗门、玄天界、魔界、妖界的阶段性冲突。

## 3. 战斗快照

战斗开始时固定：

- 角色境界、阶段、基础属性和道途状态。
- 功法、技能、装备、法器、机关和临时状态。
- 敌方配置、地点环境和规则版本。
- 初始气血、灵力、战意、污染和冷却。
- 随机池版本与随机源标识。

战斗结束后保存参与者快照、行动序列、事件日志、奖励规则和最终结果。重试只能读取原战斗，不重新抽取。

## 4. 战斗状态机与行动序列

首版采用行动序列或回合制：

1. 确定行动顺序。
2. 读取当前状态和可用技能。
3. 消耗资源并执行技能。
4. 应用伤害、治疗、护盾、控制和状态。
5. 处理持续效果和回合结束。
6. 判断胜负、逃跑、超时或阶段转换。

每个技能必须有技能键、目标、资源消耗、行动成本、冷却、效果、命中规则和日志描述。

## 5. 道途在战斗中的表现

- 体修：近战、护体、战意、承伤和低血量反击。
- 法修：元素、距离、蓄力、范围和控制。
- 器修：法器、机关、傀儡、耐久和准备时间。
- 魔修：侵蚀、契约、代价换爆发和失控事件。
- 妖修：形态、血脉、感知、环境适应和化形。
- 辅修：通过丹药、装备、阵法和服务间接影响战斗，不要求生活玩家亲自高战。

## 6. 状态效果

状态效果分为：

- 增益：攻击、护体、速度、恢复、命中等。
- 减益：虚弱、破势、沉默、迟缓、侵蚀等。
- 持续效果：持续伤害、恢复、护盾衰减和污染增长。
- 控制：眩晕、封印、束缚、驱散和行动延迟。
- 道途状态：战意、契约、血脉、化形和道基震荡。

状态必须定义叠加、刷新、覆盖、免疫、驱散和结束条件，不能只保存一个自由文本。

## 7. PVE 奖励

奖励由战斗结果、地点、贡献、轮次和奖励池共同决定。奖励可以包括修为、灵石、材料、装备、声望、线索和进入资格。

首领奖励要防止单人重复领取、多人贡献不公平和结算超时。奖励领取必须有唯一 operation。

## 8. PVP 边界

PVP 开放前需要：

- 新玩家保护和境界分组。
- 禁用或压缩不可逆资源损失。
- 赛季快照和匹配规则版本。
- 防刷分、逃跑、重复对战和协商输赢规则。
- 不影响主世界生产和生活玩家的最低体验。

## 9. 首版范围

首版实现训练战、一个探索敌人、一个精英敌人、体修/法修/器修基础技能和标准战斗回放。魔修、妖修和多人战斗先实现规则接口与测试夹具。

## 10. 实现合同

### 10.1 战斗实体

`BattleSession` 保存：

| 字段 | 说明 |
|:--|:--|
| `battle_id` | 战斗 ID |
| `battle_type` | `training`、`pve`、`elite`、`pvp`、`event` |
| `participants` | 参与者和快照 ID |
| `enemy_definition_key` | 敌方内容键 |
| `environment_key` | 战斗环境 |
| `turn_index` | 当前行动序号 |
| `state_payload` | 当前气血、灵力、状态和冷却 |
| `random_pool_version` | 随机版本 |
| `state` | `created`、`running`、`won`、`lost`、`escaped`、`expired`、`settled` |
| `replay_log` | 不可变行动和结果记录 |

### 10.2 战斗用例

`start_battle`：输入战斗类型、角色/队伍、敌方键、地点和 `operation_id`；输出战斗 ID、初始快照和第一行动者。

`submit_action`：输入战斗 ID、行动者、技能键、目标、客户端序号和 `operation_id`；服务端验证当前行动权和技能条件后执行，不接受客户端伤害值。

`resolve_battle`：输入战斗 ID、触发来源和 `operation_id`；输出胜负、回放摘要和奖励待领取状态。

错误码：`BATTLE_NOT_FOUND`、`BATTLE_BUSY`、`NOT_ACTIVE_TURN`、`SKILL_NOT_AVAILABLE`、`TARGET_INVALID`、`RESOURCE_INSUFFICIENT`、`BATTLE_EXPIRED`、`BATTLE_ALREADY_SETTLED`。

### 10.3 行动结果

每次行动记录：行动序号、行动者、技能键、目标、消耗、随机结果、伤害/治疗、状态变化、剩余资源和规则版本。

技能计算顺序固定为：目标合法性 -> 消耗预览 -> 命中/抵抗 -> 主效果 -> 状态效果 -> 持续效果 -> 胜负判断。中间失败不扣资源。

### 10.4 超时和逃跑

行动超时按战斗定义处理：自动防御、跳过、判负或结束战斗。逃跑是显式行动，成功后按规则保留/损失部分探索进度，不能通过断线模拟安全退出。

### 10.5 奖励结算

胜负结果先写入 `BattleResult`，奖励处于 `pending`；领取用独立 `claim_battle_reward` operation。训练战不产生核心资产。

### 10.6 验收样例

1. 客户端提交伪造伤害值时服务端忽略并按快照计算。
2. 非当前行动者提交技能返回 `NOT_ACTIVE_TURN`，不改变战斗状态。
3. 同一行动 operation 重试返回同一回合结果，不重复扣灵力。
4. 战斗超时和断线恢复到定义的终态，不能永久占用角色。
5. 奖励领取重试不重复生成物品、修为或灵石。
