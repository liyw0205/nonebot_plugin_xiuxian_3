# 核心玩法：经济与交易

## 1. 经济目标

经济系统让灵石、材料、生产、服务、常驻经营和世界探索互相流动；修为不作为可交易经济商品。首要目标是稳定、可追踪和防止无限通胀，而不是尽快加入复杂拍卖。

## 2. 灵石循环

灵石来源：任务、探索、生产交付、城镇委托、运输、公共建设、世界事件、宗门奖励和玩家交易。

灵石消耗：移动、配方、维修、委托、市场手续费、洞天维护、训练和部分突破准备。

系统商店和管理员发放必须有限、可审计，并且不能替代玩家间经济。

## 3. 市场类型

- 玩家委托：一方发布目标，另一方完成服务或交付。
- 摆摊：固定价格出售材料和物品。
- 受控市场：系统撮合或限价交易，首版只开放简单版本。
- 宗门仓库：成员共享或贡献兑换，权限独立。
- 世界贸易：跨玄天界、魔界、妖界的特殊材料交换。

拍卖和复杂竞价后置，只有在锁定、超时和恢复机制成熟后才开放。

## 4. 订单状态

```text
created -> accepted -> locked -> processing -> delivered -> settled
                         |           |
                         +-> cancelled/expired/failed
```

订单保存发布者、执行者、目标、价格、材料锁定、截止时间、规则版本和结算结果。

## 5. 交易不变量

- 资金和物品先锁定，再执行交付。
- 成交、撤单、过期和补偿只能发生一次。
- 订单双方不能使用同一个请求重复领取。
- 交易失败不能让资产凭空消失或复制。
- 管理员介入必须记录前后值和原因。
- 绑定物品、任务物品和公共资产遵守独立交易规则。

## 6. 价格和通胀

首版不追求复杂动态价格。价格可以由发布者决定，但系统通过以下方式控制：

- 交易手续费。
- 订单有效期。
- 生产精力和材料消耗。
- 维修和洞天维护。
- 特殊材料的地点和事件限制。
- 大量重复物品的回收或加工消耗。

价格历史只用于观察和调参，不自动决定玩家资产。

## 7. 补偿和奖励

补偿、兑换码、新手礼包和活动奖励使用奖励定义版本、资格条件、领取次数和审计记录。补偿不能绕过封禁、交易锁定或活动轮次。

## 8. 经济观测

至少记录：货币总量、每日生成/消耗、材料产出、订单成交率、失败率、锁定资产、过期订单、异常重复 operation 和管理员调整。

## 9. 首版范围

首版实现灵石流水、简单玩家委托、固定价格摆摊、材料交付和交易失败恢复。银行、复杂拍卖、跨服市场和动态税率后置。

## 10. 实现合同

### 10.1 钱包和订单字段

`Wallet` 保存角色、货币键、可用余额、锁定余额、版本和更新时间。余额变更必须生成不可变 `LedgerEntry`，包含来源、目标、前值、变化量、后值和 operation ID。

`MarketOrder` 保存订单 ID、发布者、执行者、类型、物品/资源、数量、单价、手续费、锁定记录、状态、过期时间和规则版本。

### 10.2 钱包用例

`credit_wallet` 和 `debit_wallet` 只能由明确的应用用例调用；普通查询、消息渲染和适配器不得直接改余额。

预检查：余额非负、币种存在、锁定余额不能被扣、来源 operation 合法。错误码：`WALLET_NOT_FOUND`、`BALANCE_INSUFFICIENT`、`LOCKED_BALANCE`、`CURRENCY_INVALID`、`LEDGER_CONFLICT`。

### 10.3 订单状态机

```text
created -> accepted -> locked -> processing -> delivered -> settled
   |          |          |          |
cancelled  rejected   expired    failed
```

状态迁移由服务端条件控制。`settled`、`cancelled`、`rejected`、`expired` 和 `failed` 是终态；终态不能被普通请求重新打开。

### 10.4 摆摊和委托

发布时检查物品归属和价格范围，可选择立即锁定物品或成交时锁定。建议首版发布即锁定，避免卖方在成交前消耗物品。

购买时事务顺序：锁定买方灵石 -> 锁定/确认卖方物品 -> 扣手续费 -> 转移物品 -> 结算卖方余额 -> 写订单终态。

委托生产沿用 `gameplay-production.md` 的生产订单，但报酬锁定在市场订单中，生产失败按订单约定退款或赔偿。

### 10.5 经济保护

- 单笔价格、数量和每日成交量有内容配置上限。
- 自买自卖、同账号循环转账和短时间异常成交记录风控事件。
- 过期订单由清理任务处理，清理 operation 可重试。
- 管理员补偿不能覆盖原流水，只能创建新的补偿流水。

### 10.6 验收样例

1. 买方余额不足时不锁定卖方物品。
2. 订单成交重试只转移一次物品和灵石。
3. 撤单只能由订单允许的角色执行，且锁定资产完整解锁。
4. 清理任务重复运行不重复退款。
5. 每次余额变化都能从流水重建前后余额。
