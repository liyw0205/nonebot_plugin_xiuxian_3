# 核心玩法：探索与历练

## 1. 探索目标

探索是连接地图、资源、事件和战斗的核心玩法。它不是简单的随机奖励按钮，而是由地点、风险、准备、时间和结算组成的会话。

## 2. 探索类型

- 采集：低风险获取药材、矿材、灵植和阵材。
- 历练：消耗时间和体力，获得修为、材料和事件。
- 悬赏：接受有目标、有时限、有风险的任务。
- 秘境：进入独立规则空间，完成路线或结算目标。
- 遗府：发现线索后进入的剧情探索。
- 世界事件：多人共享或分组实例的阶段性目标。

## 3. 探索会话

探索会话至少保存：

- 角色、队伍和位置快照。
- 地点、难度、环境和规则版本。
- 开始时间、预计完成时间和过期时间。
- 消耗的体力、精力、门票或灵石。
- 随机池版本、随机种子或已经确定的事件结果。
- 当前阶段、可取消状态和最终结算状态。

状态：`created`、`running`、`waiting`、`completed`、`cancelled`、`expired`、`settled`、`failed`。

## 4. 采集

采集受地点、工具、辅修、身法、资源点刷新和精力影响。采集点有：

- 内容类型和品阶。
- 当前库存和刷新时间。
- 角色资格和每日次数。
- 采集失败或遭遇事件概率。

采集结果在开始时不一定立刻生成，可以在结算时根据已保存的资源点快照生成。

## 5. 历练

历练允许玩家选择稳定、冒险或专精路线：

- 稳定路线：收益低，失败代价小。
- 冒险路线：收益高，可能触发战斗、污染或稀有事件。
- 专精路线：根据道途或辅修提高某类资源概率。

选择应影响结果分布，而不是只改变一条文案。

## 6. 悬赏

悬赏是带有 offer 快照的任务系统：

1. 刷新可选任务。
2. 玩家查看目标、消耗、时间、风险和奖励。
3. 接取一条任务并锁定次数或门票。
4. 完成目标或等待时间到达。
5. 结算奖励、声望和任务影响。

刷新次数、接取状态和结算必须按玩家与轮次隔离。不能出现没有 offer 就接取、同一悬赏重复结算或刷新后奖励变化的情况。

## 7. 秘境

秘境有独立轮次和进入资格：

- 普通进入：同一轮次按规则限制次数。
- 特殊凭证：允许额外进入，但不绕过角色忙碌、境界和队伍条件。
- 路线选择：战斗、资源、剧情或生产。
- 结算方式：完成、主动退出、失败、超时。
- 奖励：按轮次、路线和结果锁定。

秘境状态不能只依赖用户输入。所有结算读取服务端会话快照。

## 8. 随机事件

事件分为资源、战斗、剧情、选择题、交易、心魔、阵营和发现。每个事件定义：触发条件、选项、消耗、结果、冷却、重复策略和规则版本。

气运可以改变事件质量或选项出现概率，但不应让低气运玩家长期没有有效选择。

## 9. 失败与取消

探索失败可以产生：损失部分消耗、返回低级资源、进入虚弱、触发救援或获得线索。取消通常返还未使用资源，但已经发生的事件和损耗不回滚。

所有退款和补偿使用独立 operation，不能通过重复点击恢复全部资源。

## 10. 首版范围

首版实现采集、一次短历练、一个悬赏模型和一个小型洞天探索。秘境多人、复杂遗府和完整世界事件在后续版本开放。

## 11. 实现合同

### 11.1 探索会话字段

`ExplorationSession` 至少保存：

| 字段 | 说明 |
|:--|:--|
| `exploration_id` | 会话唯一 ID |
| `player_id` / `party_id` | 角色或队伍 |
| `location_key` | 探索地点 |
| `mode` | `gather`、`trial`、`bounty`、`秘境`、`遗府` |
| `risk_level` | 内容定义的风险等级 |
| `phase` | 当前路线阶段 |
| `cost_snapshot` | 已扣或已锁定的资源 |
| `random_pool_version` | 随机池版本 |
| `state` | 会话状态 |
| `result_payload` | 结算结果摘要，只在终态写入 |

### 11.2 通用会话用例

`start_exploration` 输入角色、地点、模式、路线选择、`operation_id`；输出探索 ID、预计完成时间、锁定资源和下一步动作。

`resolve_exploration` 输入探索 ID、触发来源、`operation_id`；输出事件、资源、战斗入口或完成结果。

`cancel_exploration` 只允许在内容定义的可取消阶段执行，输出退回资源和已发生损耗。

错误码：`EXPLORATION_BUSY`、`EXPLORATION_EXPIRED`、`EXPLORATION_NOT_FOUND`、`EXPLORATION_NOT_SETTLEABLE`、`OFFER_NOT_FOUND`、`DAILY_LIMIT_REACHED`、`RISK_REQUIREMENT_MISSING`。

### 11.3 采集结算

采集点使用 `GatheringNode`：节点键、地点、资源池、库存、刷新时间、每日玩家次数、保护状态和内容版本。

开始采集时锁定次数和工具；结算时读取节点快照，扣除库存并发放物品。节点库存不足返回 `NODE_EMPTY`，不能通过重试获得额外物品。

### 11.4 悬赏状态机

```text
offer_generated -> viewed -> accepted -> objective_progress
                                      -> completed -> settled
accepted -> expired/cancelled/failed
```

悬赏 offer 在生成时固定目标、期限、奖励池、声望和风险。刷新只创建新 offer，不修改已接取 offer。

### 11.5 秘境结算

秘境入口扣除门票或次数并创建 `instance_id`。路线节点由服务端保存，玩家提交的节点选择只能选择当前允许的分支。

完成、失败、退出和超时都进入唯一终态；奖励在 `settle_instance` 中一次发放。特殊凭证只能改变进入次数，不绕过角色状态和地点条件。

### 11.6 验收样例

1. 同一探索 operation 重试不重复扣体力、不重复创建会话。
2. 采集点并发领取时只有一个请求成功扣库存，其余返回 `NODE_EMPTY` 或冲突。
3. 悬赏刷新后已接任务的目标和奖励不变化。
4. 探索失败按快照应用损失，取消只退回未使用资源。
5. 秘境终态重复结算返回原奖励摘要，不重复写入背包。
