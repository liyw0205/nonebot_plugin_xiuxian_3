# 核心玩法：生产与生活

## 1. 生产链

生产链统一分为：

```text
采集 -> 加工 -> 制造 -> 鉴定/改造 -> 交付/使用/交易
```

生产系统必须有输入材料、精力、时间、配方、工具、产出质量、失败结果和订单状态。

## 2. 采集

采集由地点和生活子类共同决定：

- 药材：炼丹和灵植。
- 矿材：炼器和机关。
- 阵材：布阵和洞天建设。
- 食材：烹饪和恢复。
- 灵兽资源：驯兽、妖修和宠物内容。
- 特殊材料：世界事件和洞天福地。

采集点有库存、刷新时间、竞争规则、保护规则和内容版本。不能通过并发请求重复领取。

## 3. 炼丹

炼丹流程：选择配方 -> 检查药材和炉具 -> 消耗精力 -> 进入炼制会话 -> 结算质量、数量和副产物。

炼丹效果分类：

- 恢复丹：气血、灵力、体力或精力。
- 修炼丹：短期提高修炼收益，受周期限制。
- 突破丹：提高准备度或降低失败损失，不直接保证成功。
- 战斗丹：临时属性和状态。
- 净化丹：处理污染、心魔和负面状态。
- 特殊丹：剧情、血脉和洞天用途。

丹药不能无限永久叠加属性。永久效果应有上限、递减或使用条件。

## 4. 炼器

炼器内容：武器、防具、饰品、法器、机关、傀儡部件、符印和维修。

产出质量由材料纯度、工艺、工具、炼器熟练度、道途和随机稳定度共同决定。失败可以损失部分材料、降低耐久或生成低品质产物，但必须提前告知风险。

器修专属价值是设计和操控，不是无条件获得最高品质。

## 5. 布阵

布阵可以影响：

- 修炼环境。
- 灵田和生产速度。
- 洞天防御。
- 探索侦测和路线。
- 战斗区域效果。
- 三界通道和事件触发。

阵法需要阵基、范围、持续时间、维护成本和破解规则。阵法效果存储为结构化规则，不能直接执行任意脚本。

## 6. 灵田和洞天生产

洞天可提供灵田、作坊、仓库、阵基和访客服务。基础居所/灵田、城镇委托与商贸运输由 `gameplay/livelihood/` 定义；生产周期可以异步完成，收取 operation 必须唯一。

洞天产出受容量、灵气、维护、季节、阵法和资源点影响。聚灵类设施只能提供有限环境加成，避免成为无限乘区。

## 7. 委托生产

委托是生活玩家和战斗玩家之间的连接：

1. 委托人提供目标、材料或灵石、交付期限和品质要求。
2. 生产者接受并锁定资源。
3. 生产会话完成或失败。
4. 双方确认交付，系统结算报酬和声望。

超时、取消、拒绝和争议都有明确处理，不能由任意一方直接删除订单。

## 8. 生活子类

生活子类首批可以选择：采集、灵植、鉴定、烹饪、钓鱼、驯兽、商贸、运输和机关维护。

每个子类必须回答三个问题：谁需要它、产物如何进入循环、它如何避免被自动化或 NPC 商店完全替代。

## 9. 生产平衡

- 精力是生活玩家的主要行动预算。
- 生产时间是资源，不用单纯用灵石跳过全部成本。
- 高品质产出依赖准备和技能，随机只做小幅波动。
- 市场需求、配方消耗和维护成本共同控制通胀。
- 生产失败必须有低价值产物、经验或可追踪补偿，避免完全黑箱。

## 10. 首版范围

首版实现采集、基础药材、一个炼丹配方、一个炼器配方、一个简单阵法和一个生产委托；凡人阶段的居所/灵田与城镇生计由常驻经营域实现，产出不直接增加修为。

## 11. 实现合同

### 11.1 生产定义

`RecipeDefinition` 保存：配方键、生产类型、输入物品/数量、工具要求、境界/辅修要求、精力消耗、持续时间、质量公式、失败表、产出表和版本。

`ProductionOrder` 保存：订单 ID、生产者、委托人、配方键、输入锁定、目标品质、报价、状态、开始/结束时间、结果快照和 operation ID。

### 11.2 生产状态机

```text
draft -> submitted -> accepted -> locked -> processing
                                      |          |
                                      +-> rejected/expired
processing -> completed/failed/cancelled -> delivered -> settled
```

个人生产可以跳过 `submitted/accepted`，直接从预览进入 `locked`；玩家委托必须经过双方确认。

### 11.3 生产用例

`preview_recipe`：只读检查配方、材料、工具、时间、精力和预计质量。

`start_production`：输入配方、数量、工具、质量目标和 `operation_id`；锁定材料/精力，创建订单。

`complete_production`：输入订单、触发来源和 `operation_id`；固定生产快照，生成产物或失败副产物。

`deliver_production`：验证交付对象和订单状态，转移产物和报酬。

错误码：`RECIPE_NOT_FOUND`、`REQUIREMENT_MISSING`、`MATERIAL_INSUFFICIENT`、`ENERGY_INSUFFICIENT`、`TOOL_BUSY`、`PRODUCTION_BUSY`、`ORDER_EXPIRED`、`DELIVERY_INVALID`。

### 11.4 质量计算

```text
quality_bp = recipe_base + material_bp + skill_bp + tool_bp + environment_bp + bounded_random_bp
```

随机项只能在内容定义的范围内波动；质量等级和产出数量分别计算。生产完成后保存所有输入来源，不能用当前玩家属性重算历史订单。

### 11.5 失败处理

失败结果必须属于配方定义：

- 产出低品质成品。
- 产出副产物并返还部分材料。
- 工具耐久下降。
- 生产经验增加但订单不交付。
- 订单标记失败并进入赔偿/退款规则。

不能出现“随机失败但没有任何记录”的黑箱结果。

### 11.6 验收样例

1. 预览不会扣材料和精力。
2. 同一生产 operation 只锁定一次材料。
3. 生产者完成后，委托人未确认前产物处于待交付状态。
4. 订单过期按定义退回锁定资源，不能同时完成和过期。
5. 生产规则版本更新不改变进行中订单的质量公式。
