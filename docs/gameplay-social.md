# 核心玩法：社交与宗门

> **兼容概览，非权威。** 开发时先读[开发文档总入口](development-guide.md)，再进入[社交域](gameplay/social/)；当前状态以[当前开发状态](current-status.md)为准。

## 1. 社交目标

社交系统让不同道途互相需要，并把文字游戏从单人刷数值扩展为协作、委托、传承和共同建设。

## 2. 宗门

宗门状态包括：宗门 ID、名称、宗旨、创建者、成员、职位、贡献、仓库、公共建设、任务、声望和事件轮次。

基本流程：创建/申请加入 -> 审核 -> 成员行动 -> 贡献和建设 -> 职位权限 -> 退出/驱逐。

宗门能力：

- 功法和辅修传承。
- 公共洞天、灵田、作坊和阵法。
- 宗门任务、资源捐献和贡献兑换。
- 世界事件协作。
- 宗门声望、盟约和敌对。

宗门仓库和公共资产必须有流水，成员退出不能带走未归属公共资产。

## 3. 师徒

师徒关系用于新手引导和有限服务协助：

- 拜师申请和同意。
- 引导任务、传承内容和委托。
- 师徒贡献和毕业条件。
- 冷却、解除、失联和争议处理。

师傅不能直接替徒弟修改资产；传功或赠送必须经过受限用例并可审计。毕业奖励以地方名望、服务信誉和宗门贡献为主，不直接发修为、突破材料或概率。

## 4. 道侣和伙伴关系

道侣属于后续扩展关系，不作为首版成长刚需。可提供共同任务、双人探索、关系剧情、保护和共享建设，但不能用简单的每日点击生成无限修为。

关系建立、同意、培养、解除和冷却都必须是状态机。双方状态不一致时，以关系记录为权威。

## 5. 队伍

队伍用于探索和战斗：

- 队长、成员、邀请、同意、拒绝和退出。
- 队伍地点、准备状态和行动权限。
- 贡献计算、掉落分配和队伍解散。
- 成员掉线、超时、拒绝结算和队长离开。

队伍不能绕过个人境界、资源和冷却条件。

## 6. 委托和服务

生活玩家可以提供炼丹、炼器、布阵、鉴定、运输、采集和情报服务；居所、灵田、城镇委托、商路和公共建设见 `gameplay/livelihood/`。委托记录报价、材料、目标、质量、截止时间、交付和声誉。

服务失败或过期时，锁定资源按约定退回或转为赔偿，不能静默吞掉。

## 7. 社交资产

社交资产包括贡献、声望、关系等级、公共建设进度和荣誉。它们不能简单用灵石购买全部效果。

排行和称号按轮次结算，关系解除后保留历史记录但停止继续产出。

## 8. 权限

宗门职位权限至少分为：成员、执事、长老、副宗主、宗主。公共资产写入、成员管理、职位调整和宗门解散必须记录操作者和原因。

## 9. 首版范围

首版实现宗门创建/加入、成员和贡献、师徒申请、一个生产委托和两人探索队伍基础状态机。道侣、宗门战和跨阵营联盟后置。

## 10. 实现合同

### 10.1 宗门实体

`Sect` 保存宗门键、名称、创建者、状态、最大成员、仓库 ID、洞天 ID、贡献规则、创建时间和内容版本。

`SectMember` 保存宗门、玩家、职位、贡献、加入时间、最近行动和成员状态。一个玩家首版只能加入一个宗门。

职位权限由内容定义映射为：查看、招募、审批、仓库存取、任务管理、成员管理、建设和解散。

### 10.2 宗门用例

| 用例 | 关键输入 | 终态/输出 |
|:--|:--|:--|
| `create_sect` | 名称、宗旨、`operation_id` | 宗门和创建者成员 |
| `apply_sect` | 宗门、玩家、申请说明 | `pending` 申请 |
| `review_member` | 申请、同意/拒绝、原因 | 成员或拒绝记录 |
| `contribute_sect` | 资源、建设目标、`operation_id` | 资源流水和贡献 |
| `change_role` | 目标成员、职位、原因 | 成员职位变更 |
| `leave_sect` | 玩家、`operation_id` | 成员离开和公共资产处理 |

错误码：`SECT_NOT_FOUND`、`SECT_FULL`、`ALREADY_MEMBER`、`APPLICATION_EXISTS`、`SECT_PERMISSION_DENIED`、`SECT_ASSET_LOCKED`、`ROLE_CHANGE_INVALID`。

### 10.3 师徒和队伍

关系记录保存发起方、接受方、关系类型、状态、邀请过期时间、贡献、冷却和规则版本。

```text
invited -> accepted -> active -> graduated/ended
invited -> rejected/expired
```

队伍记录保存队长、成员序列、地点、准备状态、当前会话、掉线时间和分配规则。队伍行动必须再次检查每个成员资格，不能只检查队长。

### 10.4 资产和争议

宗门公共资产、师徒赠送、委托材料和队伍奖励都需要独立流水。关系解除不回滚已经完成的服务；未交付资产按关系/订单状态处理。

### 10.5 验收样例

1. 非管理职位修改成员或仓库返回权限错误且无资产变化。
2. 同一申请不能重复创建，过期申请不能被接受。
3. 队长离开时按规则转移队长或解散队伍，不能留下不可结算队伍。
4. 队伍中任一成员不满足地点条件时创建探索失败，不扣全队资源。
5. 宗门贡献重试只增加一次贡献和一次资源流水。
