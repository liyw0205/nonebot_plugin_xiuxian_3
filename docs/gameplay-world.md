# 核心玩法：三界与地图

> **兼容概览，非权威。** 开发时先读[开发文档总入口](development-guide.md)，再进入[世界域](gameplay/world/)；当前状态以[当前开发状态](current-status.md)为准。

## 1. 世界层级

```text
三界主世界
├── 玄天界：人族修行文明和主要新手区域
├── 魔界：魔族、魔渊、契约和侵蚀
└── 妖界：妖族、祖地、血脉和化形

小世界
├── 洞天：规则稳定、资源完整、可建设
└── 福地：资源集中、规则特殊、风险更高
```

洞天/福地不是单纯副本名称，而是带有地点规则、生态、入口、时间、资源和事件的小世界。

## 2. 地点模型

每个地点定义：

- `location_key` 和所属世界。
- 进入境界、道途、声望和任务条件。
- 移动时间、体力/灵石消耗和冷却。
- 环境系数、可采集资源、事件池和战斗池。
- 是否允许组队、生产、交易或建设。
- 退出、失败、死亡和过期规则。
- 地点规则版本和开放时间。

玩家位置是角色状态的一部分，跨地点行动必须通过移动用例完成。

## 3. 玄天界

首版玄天界至少包含：

- 新手城：凡人生活、任务、市场和入道引导。
- 近郊荒野：采集、低风险战斗和第一次探索。
- 宗门山门：拜师、入宗、功法和公共建设。
- 灵脉区域：修炼环境、灵植和争夺事件。
- 第一处洞天入口：连接探索、生产和剧情。

玄天界是默认起点，不代表所有玩家必须长期留在人族路线。

## 4. 魔界

魔界是半个大世界，首批可用内容：

- 魔渊入口：高侵蚀资源和短期高收益。
- 契约集市：特殊交易、契约和风险兑换。
- 堕落遗迹：战斗、心魔和历史线索。
- 魔族领地：声望、敌对和阵营剧情。

进入魔界需要境界、任务、阵营或特殊通道条件。魔修拥有更低的部分进入门槛，但承担侵蚀和失控风险。

## 5. 妖界

妖界是半个大世界，首批可用内容：

- 万兽山：采集、驯兽、狩猎和妖族关系。
- 化形圣地：妖修形态、血脉和剧情选择。
- 妖族祖地：高阶血脉资源和族群任务。
- 三界贸易口：跨阵营委托和材料交换。

妖界内容不应被设计成纯 PVE 敌方地图，妖族 NPC、玩家和宗门可以建立盟约、贸易或敌对关系。

## 6. 洞天与福地

洞天偏向建设、生产和长期经营：

- 灵田、炼丹房、炼器台、阵基和仓库。
- 灵气浓度、时间流速和维护成本。
- 宗门或个人所有权。
- 访客、委托、保护和入侵规则。

福地偏向探索和风险：

- 稀有资源、特殊事件、遗府和隐藏路线。
- 进入次数、天气/时间、随机事件和风险上限。
- 发现记录和一次性剧情奖励。

洞天福地的收益不能无限叠加，必须有维护、容量、产出周期和规则版本。

## 7. 移动流程

```text
查看当前位置
  -> 查看目标要求和路程
  -> 预检查冷却、体力、队伍和战斗状态
  -> 扣除移动资源并创建移动会话
  -> 到达或遇到途中事件
  -> 写入新位置和结果
```

移动中的玩家不能重复创建另一条移动会话。中断、超时和网络重试都必须幂等。

## 8. 世界事件

世界事件可以是：灵脉出现、魔界入侵、妖界贸易、洞天开启、宗门冲突、灾害、遗迹降临和跨群协作。

事件定义：轮次、参与资格、阶段、贡献方式、奖励池、阵营影响、开始/结束时间和结算版本。

## 9. 地图开放

地图开放采用内容配置和条件表达，不把权限写死在命令处理器。条件包括境界、任务、声望、道途、物品、时间窗口和前置事件。

## 10. 首版范围

首版实现玄天界新手城、近郊荒野、宗门山门、一个洞天或福地、移动、地点状态、采集点和一个世界事件入口。魔界和妖界先完成入口、条件和占位叙事。

## 11. 实现合同

### 11.1 地点定义

`WorldLocation` 内容定义至少包含：

| 字段 | 说明 |
|:--|:--|
| `location_key` | 稳定地点键 |
| `world_key` | `xuantian`、`demon`、`beast`、`cave`、`blessed` |
| `parent_key` | 所属区域或入口 |
| `entry_requirements` | 境界、任务、声望、道途、物品条件 |
| `travel_cost` | 体力、灵石或时间消耗 |
| `environment_modifiers` | 灵气、风险、资源和战斗修正 |
| `allowed_actions` | 移动、修炼、采集、生产、交易、战斗等 |
| `event_pool_key` | 途中或地点事件池 |
| `content_version` | 内容版本 |

### 11.2 玩家位置

`PlayerLocation` 保存 `player_id`、当前位置、移动状态、到达时间、队伍 ID、最后结算 operation 和位置规则版本。

移动会话保存起点、终点、创建时间、预计到达时间、实际费用、途中事件、状态和结果。

### 11.3 移动用例

输入：角色、目标地点、移动方式、`operation_id`。

预检查：目标存在、入口条件满足、角色不在战斗/生产锁定/突破中、没有进行中的移动、资源足够。

成功：锁定并扣除移动费用，创建 `travel_session`，返回预计到达时间。

完成：由玩家查询、定时任务或事件驱动结算，写入当前位置、途中事件和结果。

错误码：`LOCATION_NOT_FOUND`、`LOCATION_LOCKED`、`TRAVEL_BUSY`、`PLAYER_OCCUPIED`、`TRAVEL_RESOURCE_INSUFFICIENT`、`TRAVEL_ROUTE_INVALID`。

### 11.4 地点与移动状态机

```text
location: locked -> open -> closed
travel: created -> running -> arrived
                         \-> interrupted/expired/failed
```

地点关闭不会强制删除已在其中的玩家；后续行动按撤离、封锁或事件规则处理。

### 11.5 验收样例

1. 不满足入口条件时移动不扣体力、不创建移动会话。
2. 重复移动请求返回同一会话，不能重复扣费。
3. 到达结算重复执行只写入一次位置变更和途中事件。
4. 地点规则版本更新不改变已经完成的探索或战斗结果。
5. 魔界/妖界入口可以在未开放完整内容时返回明确的 `LOCATION_LOCKED` 和开放条件。
