# 战斗内容合同 v1.0：玄武岩径古渠守标

本合同扩展普通四至五人自动 PVE，不改变既有队伍会话、行动推进、资产锁、贡献及唯一奖励表。
运行时仍从 `data/战斗/敌人.json` 读取唯一 `standard_pve` 敌人；队伍开战冻结敌人、准入、随机池和奖励。

## 遭遇

| 字段 | 合同 |
|:--|:--|
| 敌人 | `enemy.basalt_canal_marker`，古渠守标，地点 `xuantian.basalt_pass` |
| 准入 | 聚气二层，地点实际移动条件仍取玄武岩径地图记录 |
| 属性/技能 | 620 气血、34 攻击、12 先手、10 身法；服务端使用 `enemy_skill.blade_wave` |
| 队伍 | `standard_pve`，四至五名队员，全员同地、满足境界、确认且无冲突行程；队长开始 |
| 入场 | 每人十体力、二精力；按敌人与 UTC 开战日每人一次，更换队伍或重启不重置 |
| 胜利奖励 | 每名有贡献成员 75 修为、28 灵石、铁石一份、阵砂一份 |
| 来源 | `source.party.basalt_canal`，仅声明 `battle.party.resolve` 对应的敌人与材料；不创建第二发奖入口 |
| 消费者 | 铁石用于野外修缮包等开放配方；阵砂用于山河罗盘、基础聚灵阵等开放配方 |

只读预览展示所有成员的资格、地点、确认、剩余资源、次数与阻碍，以及冻结将要使用的成本和奖励。
所有成员通过预检后，在同一事务内扣除入场成本、占用队伍和成员锁并创建服务端战斗；不接受客户端行动或结果。
战败、超时均计入次数且不退入场成本、不发胜利材料。有贡献的胜利成员按 `(battle_id, player_id)` 唯一结算；
重复 operation 回放原结果，同 operation 不同输入冲突。任一参战成员可在重启后继续结算与读取原战局。
内容关闭阻止新战斗，但不重算或阻断已开始战斗的冻结快照。

官方敌人与来源种子各记录真实旧/新 SHA-256 及 Git 来源。安装器只升级已知官方旧种子，自定义内容不被覆盖；
自定义种子若与严格来源合同冲突，则验载回滚并报告，不补隐式来源或奖励。无数据库 schema 变化。

聚焦证据：`test/test_party_standard_pve.py`、`test/test_party_pve_content.py`、
`test/test_basalt_party_seeds.py` 及内容、帮助和适配器测试。
