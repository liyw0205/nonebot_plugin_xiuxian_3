# v0.8 灵兽战技：装配与普通 PvE

## 内容合同

`data/灵兽/战技.json` 使用 `kind=companion_technique`。每条记录严格包含：

| 字段 | 合同 |
|:--|:--|
| `key` | 唯一 ASCII 键，前缀 `technique.beast.` |
| `name` / `desc` | 非空玩家名称与说明 |
| `compatible_species` | 非空、无重复的开放灵兽键；只能列 `kind=beast` |
| `slot_no` | 1 或 2，且不能超过解锁蜕变的 `skill_slots` |
| `unlock_evolution_key` | 开放灵兽蜕变；其目标必须是每个兼容物种的祖先形态 |
| `effect` | 仅接受严格 `{type, value}` 对象；效果为 `opening_attack_bp` 或 `first_guard_bp`，`value` 为 1–5000 bp |
| `status` | `active` 或 `locked`；只有开放且兼容当前灵兽的记录可装配 |

当前官方内容为踏风先声（铁背鼠、玉背鼠灵窍 1，首次主动攻击 +1800 bp）、根甲护主
（同物种/槽位，首次实际受击 -1500 bp）与青玉共鸣（玉背鼠灵窍 2，首次实际受击 -1200 bp）。
多项同触发效果按总和计算，合计最多 5000 bp；各项在触发时一起消耗。

## 持久装配

`companion_technique_loadouts` 以角色、灵兽实例、槽位、战技键和 operation ID 保存当前装配，
槽位与同灵兽重复战技均有唯一约束。向前迁移幂等建表，不改写灵兽、玩家、operation 或战斗历史。
装备/卸下在 `BEGIN IMMEDIATE` 中检查玩家写权限、实例归属、灵兽类型、随行/战斗锁、槽位开放、
物种适配和当前内容状态，再保存新装配与 operation 回执；相同请求重放原回执，operation ID 冲突拒绝。
卸下过期/关闭内容仍可清理，不允许新战斗消费不再适用的旧装配。

命令通过 QQ 官方和 OneBot V11 共用应用：

```text
灵兽战技 <灵兽编号>
装配灵兽战技 <灵兽编号> <灵窍> <战技名或键>
卸下灵兽战技 <灵兽编号> <灵窍>
```

## 战斗闭环

探索开始快照携带该角色出战灵兽的战技键、名称、槽位和完整效果值。探索遭遇开战沿用该冻结快照；
普通 `standard_pve` 组队战在开战事务中为每名成员冻结各自出战灵兽，队员不能借用他人装配。
首次非蓄力主动攻击应用 `opening_attack_bp`；首次受到正数敌方伤害应用 `first_guard_bp`。
效果从服务端的冻结数据确定性计算，消费标记写入会话状态，每条 action/state 记录触发键、值、变化量，
战斗回放不访问现有装配或当前内容。

没有战技的历史快照沿用原伤害路径。专属秘境、PvP、竞技、试炼和其他既有战斗策略保持不变。
验收需覆盖双适配器真实命令、错误准入与冲突重放、迁移/重启、探索及普通组队效果/成员隔离、
冻结后改装/改内容和 action replay；仅运行直接受影响的灵兽、内容、种子迁移、探索、战斗、组队、帮助与文档测试。
