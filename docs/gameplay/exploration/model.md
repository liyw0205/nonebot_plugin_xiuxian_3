# 探索域：会话模型

`ExplorationSession`：`exploration_id`、角色/队伍、地点、模式、风险、路线阶段、费用快照、随机池键、状态和结果摘要。
开始时还冻结 `realm_key`/`realm_layer`、资质、道途、基础气血/先手、装备快照、遭遇概率、
规则参数和随机种子。近郊采集、短历练、灵泉采集、雾隐洞天探索、云铁矿区采集、云舟试炼、万兽山狩猎、深渊门备材、魔界堕落遗迹、祖灵湖探索、云城护送和灵田巡护同时冻结 `reward_pool_key` 和实际 `frozen_result`，
结算不再读取奖池或重新抽取；洞天二层探索也冻结联合奖池与实际结果。云舟风暴只改变冻结结果的结算分支，不重新抽取。遭遇创建后在结果摘要中保存 `battle_id`、敌人键和 `battle_outcome`，
以便重启恢复与幂等回放；战斗模式按胜负从开始快照读取对应收获，未配置战败收获时败退不发探索奖励。

万兽山狩猎与魔界堕落遗迹探索的无收获分支由奖池中的 `no_reward: true` 表示，不创建额外事件或资产；奖池声明 `item_weight_bonus: true` 时，构筑福缘与出战灵兽的探索发现率只提高含物品结果的权重，不改变声望与无收获结果。探索开始冻结体质/灵兽效果、合并权重和实际结果，重启与结算不重算。祖灵湖奖励由两条加权结果提供（原固定奖励为主、一份变体为辅），不启用发现权重或战败保底；其结算按开始时冻结的稳定度快照下降 5，真实遭遇败退不发探索奖励。

深渊门备材同样由两条加权结果提供（神魂晶与魔核各一枚为主、魔核加一的变体为辅）；该模式没有战斗遭遇、福缘加权或战败保底。结算复用探索资产事务，魔核的 24 小时绑定流水按实际发放数量生成。两者原有确定冻结结果与幂等回放仍由占绝对权重的主结果保持。

灵泉采集当前没有战斗遭遇，灵叶、阵砂与灵泉水的产出由内容奖励池决定；未抽中阵砂时不写零数量物品。
结算在同一事务发放冻结奖励并按实际灵叶数量投影灵泉事件贡献，轮次按探索开始时间归属，来源按开始
operation 去重。没有灵叶或探索已过期时不贡献；内容改值、重启和重复结算不得改变已开始的收获。

雾隐洞天探索的修为与洞天材料从同一个联合奖池抽取。单次结果包含一份修为及一种材料；开始后改动内容
不会改变其实际收获，遭遇战胜利发放该结果，失败不发放。材料获得记录和奖励均由探索结算事务完成。

云铁矿区采集从当前内容奖池抽取并冻结云铁数量，矿兽战胜利发放该收获，失败按同一奖池冻结的战败收获发放。

筑基期在云城与灵泉谷另有云城护送、灵田巡护两条探索模式，复用通用探索会话、加权奖池、
遭遇池与每日次数合同：两者均在开始冻结 `reward_pool_key` 与 `frozen_result`，按各自 `battle_chance_bp`
以随机种子判定是否遭遇同地点的真实敌人（劫修学徒 / 灵泉水灵），战斗胜利发放冻结收获、败退不发探索奖励；
每日上限均为 5 次。对应图鉴条目记录完成后的见闻，不改变既有命令、资产事务或幂等回放语义。

`GatheringNode`：节点键、地点、资源池、库存、刷新时间、玩家次数和保护状态。

`BountyOffer`：offer 键、轮次、目标、期限、风险、奖励池、声望和接取状态。生成后目标与奖励固定。

探索会话状态中的 `combat_pending` 只表示遭遇战尚未完成，不是可直接领奖的终态；最终结果
必须关联已 `settled` 的 `BattleSession`。
