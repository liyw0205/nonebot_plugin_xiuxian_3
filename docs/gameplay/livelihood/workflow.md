# 常驻经营域：状态机

```text
residence: inactive -> leased -> active -> overdue -> released
plot: empty -> planted -> growing -> harvestable -> harvested
                         \-> withered
commission: published -> accepted -> delivered -> settled
                         \-> cancelled/expired
service_order: draft -> published -> accepted -> locked -> processing -> delivered -> settled
                                                          \-> failed/expired/cancelled
trade_route: in_transit -> settled
project: proposed -> active -> maintenance_due -> inactive
```

锁定材料、报酬、货物和维护费后才能进入可结算状态。相同 `operation_id` 回放同一状态/结果；相同 ID 而输入不同返回冲突。服务端业务日、地点库存、市场订单和角色会话锁共同决定配额，客户端时间与展示按钮不拥有结算权。

灵田新请求只从当前角色名下挑选地块，不联到当前租约筛除旧作物。收获从已成熟且尚未枯萎的活动作物中，按 `wither_at`、地块 ID 升序取一块；维护从未成熟且维护次数少于要求的活动作物中，按 `harvest_at`、地块 ID 升序取一块。已枯萎、已完成照料或时间未到的地块不得遮挡其他符合条件的作物。查看灵田沿用收获优先的顺序，其次显示最早成熟的生长作物；仅在没有活动作物时显示最近的终态地块。成熟时刻起可以收获、不能再维护，超过枯萎时刻才视为枯萎。

播种仍需有效租约、空地、种子和精力；当前租约中的已枯作物不再占用可播种地块，按严格快照确认枯萎后，与新播种一起提交腾地状态，不清理其他租约仍在生长的作物。播种失败时腾地状态和费用一并回滚。租约到期后旧作物继续按播种快照维护与收获，重租只影响新播种归属。变更请求先核对 operation 历史结果，再选择和校验当前地块；原请求重放不会转向另一块地，也不依赖当前作物内容是否开放。候选快照严格解码，损坏时整笔拒绝，不因另有正常地块而静默略过。维护费用、收获物品与名望、地块状态、图鉴见闻和 operation 账本在同一事务提交；错误分支与任一写入失败均回滚，不单独提交枯萎或成熟状态，不留下已扣精力、已发物品或半笔见闻。同请求故障重试和停机恢复不改变地块选择规则，已经成功的请求只回放原结果。

播种冻结作物名称和全部潜在收成的 `harvest_labels`，包括照料副产物。查询、收获与历史 operation 回复使用这些名称和中文状态，不因当前物品改名、关闭或删除而变化。快照与历史 operation 使用共享的严格 JSON 解码，重复字段不能覆盖已记录的奖励；缺失必需字段直接拒绝，不构造旧格式默认值。

城镇委托按业务日冻结需求、报酬、地方名望键和地点名望上限；接取时复制该快照并只占用名额，
不扣物品。交付由共享角色状态事务同时扣除所需材料、发放灵石、增加地方名望和服务信誉，
委托状态、名望/信誉前后值与 operation 账本在同一事务提交。交付回复记录实际增加的名望和信誉，
封顶时不虚报额外所得；若已有名望超过旧单上限，奖励不再增长但不得扣回已有名望。重启、重放和
故障后重试均沿用已冻结的需求、报酬、名望键与上限，新的基础内容只用于新业务日委托。
名称解析不触发奖励校验，已接取委托可在内容关闭后交付；operation 优先读取历史结果，新接取才
校验当前开放规则。服务端日期不属于接取请求输入，跨日重放不占新名额。异常不得留下已扣材料、
已发报酬或半交付记录。

短途运输预览只读，不锁货物、不扣体力、不占次数。开始运输先校验当前生活内容、角色阶段、
起点、货值、体力、次数和会话锁，在同一事务扣除货物与体力、更新灵骑随行状态，冻结路线
报酬、地方名望键/地点上限、货物及名称、延误结果与灵骑快照。抵达是时间条件，不新增持久化
状态；仅从出发快照结算，通过共享角色状态事务发放灵石、增加名望并更新目的地；灵骑经验/
受伤状态、路线状态、实际名望前后值与 operation 同事务提交。封顶不扣回超过旧上限的已有
名望，不虚报增量。内容关闭或调整只
影响新运输，历史开始/结算请求先重放 operation；不同输入仍冲突。名望、路线或账本写入失败
不得留下已发报酬、已移动角色、已结算路线或单独成长的灵骑，恢复后可用同一请求重试。
未指定货物的请求在账本校验后才解析配置中的默认货物，默认货物变更不改变历史开始结果。
当前没有主动取消、运输失败或过期退货入口；结算异常保留已锁的出发成本。

公共项目由服务端业务周物化。名称、说明、需求、可贡献资源、奖励、名望地点与上限、服务来源和成效文案在物化时冻结；后续内容调整只影响新项目。材料贡献按冻结的资源与需求校验单次 30 点上限，再同步扣除资源、记录贡献和更新进度；服务贡献按冻结来源，在同一事务核验本人已成功结算的来源、状态与唯一使用，再记录固定服务点数，不再次扣费。达到所有资源目标立即进入 `active` 并冻结 7 天成效窗口。累计贡献至少 10 点的已完成项目才可领奖，奖励从项目快照读取，经共享角色状态事务发放；资产、实际名望/行旅声望增量、领奖记录和 operation 同事务提交，并以 `(project_id, player_id)` 保证奖励唯一。内容关闭不阻断已物化项目结算或历史 operation 重放；坏名望 JSON 或任一阶段写入失败均回滚整笔奖励，原请求可重试。

服务订单由发布、接取和结算三段组成。发布时按当前 `service` 内容校验准入与报酬范围，从委托人灵石中锁定报酬，并冻结服务名称、成本、交付物、失败返还、地点要求、次数和期限。接取只按冻结成本检查并扣除承接者体力、精力和材料，同时写入承接状态；同一订单不能重复承接。结算先读取订单快照：同地点或明确允许异地时成功，发放承接者的 98% 报酬和委托人交付物；异地、期限届满或其他失败条件按快照返还委托人 80% 报酬，并返还配置声明的承接者材料与体力。期限届满的接取请求会将订单标为 `expired`，退回全部锁定报酬并把退款结果写入该 operation；相同 operation 只回放结果。订单状态、玩家资产/数值和 operation 必须在同一 SQLite 事务提交，故障回滚后原请求可重试，运行中修改或关闭内容不影响已发布订单。
