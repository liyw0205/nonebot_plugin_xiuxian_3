# 核心：道历与运营循环域

本域把签到、补签到、灵木聚财、日/周/月道契、机缘寻宝、问道行卷、道号、功业录、七日入道与兑换密令统一为可审计的核心运营系统，不属于娱乐功能。

## 当前实现切片

当前可运行切片开放道历问安、补录道历、灵木聚财、七日入道进度/领奖、称号/功业录、基础机缘寻宝，以及配置注入的机缘密令：

```text
道历问安
补录道历 YYYY-MM-DD
浇灌灵木
收获灵木
七日入道
领取七日目标 日数
功业录
领取功业 序号
佩戴称号 序号
兑换密令 密令内容
我的道契
激活道契 凭证
领取道契 日/周/月
机缘寻宝 [单抽|十连]
问道行卷
开始行卷
领取行卷 <等级> [免费|付费]
```

它们共用 application 身份校验、SQLite 短事务和 operation ledger。签到日期、补录窗口、
灵木浇灌次数及收获周期都由服务端业务日决定；资产变化、业务记录和 operation 必须在同一
事务中提交。七日入道按首次寻仙问道 operation 的业务日建立固定起点，目标可以补做但不能
重置；D5 接受试炼塔第一层胜利来源，D6 只接受事务内投影的已结算派遣来源 operation。称号从已落库的寻仙问道/运营来源投影，功业奖励领取使用独立
operation 和唯一约束；图鉴五条首见、首次派遣及试炼塔十层功业来源已接入。机缘寻宝基础池已开放：单抽优先消耗机缘签，
十连消耗 450 灵石，结果按 operation 派生确定性种子并保存保底快照。道契使用
外部签名测试凭证激活，支持日/周/月周期权益；同商品续期从当前结束日顺延，撤销停止未来
领取但不回收已发权益。机缘密令
由 `XIUXIAN3_REDEMPTION_CODES` 注入，运行时只保存密令哈希；每条密令有总库存、有效期和撤销
状态，按角色唯一领取，领取结果与资产更新和 operation 在同一事务提交。问道行卷 v0.1
已开放：周期 28 日、30 级，每级 80 行卷点；每日最多计入 100 点、每周最多计入 500 点。
点数只从已结算 operation 投影，来源 operation 每周期只能绑定一次。免费线奖励材料、名望
和展示称号；付费线必须有当前有效的月道契，只发放展示称号、配方线索和灵木水分券，不发放
修为、境界或突破物。

灵木收获从 `reward_pool.routine.spirit_tree_harvest` 读取联合奖励；奖池键、种子摘要与实际结果
随收获 operation 冻结。灵石、种子和地点名望通过共享角色状态事务一并发放，地点名望上限取自
地点内容记录。

功业、机缘密令、道契和问道行卷的资产、精力、地方名望与服务信誉统一由
`utils.player.grant_player_reward_actual` 结算；规则只提供奖励和地点键，地点/资源上限由当前内容读取。
领取记录和 operation 只保存实际到账，损坏名望数据会令整笔事务回滚，同一 operation 重放不重复发放。

## 资产边界

- 道历、灵木、道契和行卷奖励使用业务日/周/月份快照，不能用客户端时间补领。
- 道契的购买/支付由外部 billing adapter 提供凭证；核心只验证签名、商品键、周期和 entitlement，不保存银行卡/支付秘密。
- 机缘寻宝的随机池、保底、消耗和实际结果必须快照；禁止使用未声明的高阶境界/终局资源池。
- 道号和功业默认是展示或资格，不直接提供永久战斗倍率；内容明确的轻量效果也必须进入属性 modifier 上限。
- 兑换密令不允许直接执行 SQL/资产变更；一个密令按 `code_key + player_id` 唯一领取，可撤销但不能回收已合法发放资产。

## 共享字段

`RoutineClaim`：角色、活动键、业务窗口、资格快照、奖励包、状态、领取时间、内容/规则版本、operation ID。

`Entitlement`：角色、商品键、周期、来源凭证摘要、开始/结束、权益状态、撤销原因、版本。

`RewardPoolRoll`：池键、权重/保底版本、消耗、随机种子摘要、实际结果、operation ID。

`HonorRecord`：道号/功业键、触发来源、获得时间、展示状态、历史版本；已获得记录不可删除，只能隐藏展示。
