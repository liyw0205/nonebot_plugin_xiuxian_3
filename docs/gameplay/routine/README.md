# 核心：道历与运营循环域

本域把签到、补签到、灵木聚财、日/周/月道契、机缘寻宝、问道行卷、道号、功业录、七日入道与兑换密令统一为可审计的核心运营系统，不属于娱乐功能。

## 当前实现切片

当前可运行切片开放道历问安、补录道历、灵木聚财、七日入道进度/领奖、称号/功业录、基础机缘寻宝，以及配置注入的机缘密令：

```text
道历问安
补录道历 YYYY-MM-DD
浇灌灵木
收获灵木
七日入道
领取七日目标 日数
功业录
领取功业 序号
佩戴称号 序号
兑换密令 密令内容
我的道契
激活道契 凭证
领取道契 日/周/月
机缘寻宝 [单抽|十连]
问道行卷
开始行卷
领取行卷 <等级> [免费|付费]
```

它们共用 application 身份校验、SQLite 短事务和 operation ledger。签到日期、补录窗口、
灵木浇灌次数及收获周期都由服务端业务日决定；资产变化、业务记录和 operation 必须在同一
事务中提交。七日入道按首次寻仙问道 operation 的业务日建立固定起点，目标可以补做但不能
重置；D5 接受试炼塔第一层胜利来源，D6 只接受事务内投影的已结算派遣来源 operation。称号从已落库的寻仙问道/运营来源投影，功业奖励领取使用独立
operation 和唯一约束；图鉴五条首见、首次派遣及试炼塔十层功业来源已接入。机缘寻宝基础池已开放：单抽优先消耗机缘签，
十连消耗 450 灵石，结果按 operation 派生确定性种子并保存保底快照。道契使用
外部签名测试凭证激活，支持日/周/月周期权益；同商品续期从当前结束日顺延，撤销停止未来
领取但不回收已发权益。机缘密令
由 `XIUXIAN3_REDEMPTION_CODES` 注入，运行时只保存密令哈希；每条密令有总库存、有效期和撤销
状态，按角色唯一领取，领取结果与资产更新和 operation 在同一事务提交。问道行卷
已开放：默认周期 28 日、30 级，每级 80 行卷点；每日最多计入 100 点、自然周最多计入 600 点。
原周上限 500 使满级 2400 点在任意开启星期都不可达；600 是在保留其余周期参数时满足四周目标的最低上限。
点数只从已结算 operation 投影，来源 operation 每周期只能绑定一次。免费线奖励材料、名望
和展示称号；付费线必须有当前有效的月道契，只发放展示称号、配方线索和灵木水分券，不发放
修为、境界或突破物。

机缘寻宝实际获得的材料，在扣费与发奖的同一事务内交给既有材料图鉴投影；只收入当前开放且已登记的
材料条目，灵石、名望、丹药等其他所得不凭空生成材料见闻。首见保存来源 operation、奖池键、时间和
材料展示名；后续所得不得覆盖首见。保底、抽取记录、图鉴与 operation 任一写入失败，扣费和全部所得
一并回滚。重复请求只读回放原结果，不重新抽取，也不为历史漏记补写图鉴；保持引用闭合的内容改名或
关闭，不改变已保存的抽取结果与首见展示。

行卷唯一规则来源为 `data/道历/行卷.json`。开卷时冻结周期、门槛、日周上限、来源点数、两条奖励线、
地方名望地点/上限及展示名；同一周期不重新读取现行内容。只投影寻仙问道、问安、灵木浇灌/收获、生产完成、
悬赏领奖、探索结算、道契领取八种既有服务端来源；接取悬赏不计分，近郊采集不与探索结算重复计分。
周期按 UTC 业务日含首尾两日计算，同一自然周以周一为起点；点数同时受日、周及周期满级总量封顶。
内容关闭只阻止新开卷，已开周期按原快照继续计分与领奖；周期结束后查询先补投影周期内的真实来源，
再关闭周期，不得新领奖。未到期满级仍可领取已解锁奖励，满级周期到期后同样关闭。原 operation 优先回放，
不受当前内容、周期到期或月道契失效影响；
新付费领奖仍要求当前有效月道契。坏JSON/快照拒绝，不按旧格式或默认值补齐。

灵木收获从 `reward_pool.routine.spirit_tree_harvest` 读取联合奖励；奖池键、种子摘要与实际结果
随收获 operation 冻结。灵石、种子和地点名望通过共享角色状态事务一并发放，地点名望上限取自
地点内容记录。

功业、机缘密令、道契和问道行卷的资产、精力、地方名望与服务信誉统一由
`utils.player.grant_player_reward_actual` 结算；规则提供奖励、地点键和上限，行卷的地方名望上限
在开卷时从地点内容读取并冻结，领奖不得重新读取现行地点上限。
领取记录和 operation 只保存实际到账，损坏名望数据会令整笔事务回滚，同一 operation 重放不重复发放。

## 资产边界

- 道历、灵木、道契和行卷奖励使用业务日/周/月份快照，不能用客户端时间补领。
- 道契的购买/支付由外部 billing adapter 提供凭证；核心只验证签名、商品键、周期和 entitlement，不保存银行卡/支付秘密。
- 机缘寻宝的随机池、保底、消耗和实际结果必须快照；禁止使用未声明的高阶境界/终局资源池。
- 道号和功业默认是展示或资格，不直接提供永久战斗倍率；内容明确的轻量效果也必须进入属性 modifier 上限。
- 兑换密令不允许直接执行 SQL/资产变更；一个密令按 `code_key + player_id` 唯一领取，可撤销但不能回收已合法发放资产。

## 共享字段

`RoutineClaim`：角色、活动键、业务窗口、资格与规则快照、实际奖励、状态、领取时间、operation ID。

`Entitlement`：角色、商品键、周期、来源凭证摘要、开始/结束、权益状态、撤销原因。

`RewardPoolRoll`：池键、权重/保底快照、消耗、随机种子摘要、实际结果、operation ID。

`HonorRecord`：道号/功业键、触发来源、获得时间、展示状态；已获得记录不可删除，只能隐藏展示。

`WayfaringPass`：角色、行卷键、起止业务日、状态、规则快照、积分、日周计入量和两条奖励线的已领取等级。
规则快照包含来源、奖励、展示名及地方名望上限，不保存内容或规则版本标识。
