# 道侣共修

道侣共修以双方主动同意作为结算条件。双方须持有当前有效道侣关系、处于活跃角色状态、位于同一开放共修地点，并达到 `social.partner_cultivation` 配置境界；任何一方在进行中的修炼、探索、战斗、生产、远征或其他锁定行动中时均不能发起或接受。

## 命令

| 命令 | 用途 |
|:--|:--|
| `双修预览` | 查看道侣、共同地点、各自成本、本人可得修为、UTC 当日次数和待处理邀请 |
| `双修状态` | 查看当前资格与最近邀请 |
| `发起双修 <道号>` | 发出有时限的邀请；不预扣资源 |
| `接受双修 <邀请号>` | 由指定道侣确认，并在一个事务中完成双方结算 |
| `拒绝双修 <邀请号>` | 由指定道侣拒绝 |
| `取消双修 <邀请号>` | 发起者撤回待处理邀请 |

规则内容在 `data/社交/双修.json`。当前开放青石镇和云上城，需元婴一层；邀请 10 分钟失效，每人每天 UTC 最多结算两次。接受时双方各扣 100 灵石和 5 精力。修为按本人当前境界层剩余区间的 2% 计算，限制在内容定义的 1 至 1500 之间，并且不会跨过本层晋升阈值。双方独立计算、独立到账；不转移或共享资产，不自动晋层、突破或改变关系。

## 状态与事务

```text
invited -> settled
    |----> rejected
    |----> cancelled
    `----> expired
```

邀请保存关系、地点、规则快照与指纹。接受时重新检查邀请对象、关系状态、双方角色、地点、活动锁、修为阈值、资源和各自 UTC 日额度。结算表以邀请和玩家为复合主键；角色状态、个人流水、邀请终态和接受 operation 在同一 SQLite 事务提交。任何一方失败则全部回滚，待邀请可在状态恢复后重试。

operation 输入相同会回放已冻结结果；同 ID 不同输入冲突。进程重启不重新计算已结算修为。并发接受由事务串行化，只有一个请求能完成双人结算。规则关闭会阻止新邀请，但不会重写有效邀请快照；过期、拒绝和撤回有持久状态及可重放回执。查询只投影本人相关的道号与邀请号，不暴露平台 ID 或数据库编号。

## 持久化与边界

`partner_cultivation_invitations` 与 `partner_cultivation_settlements` 是可重复初始化的增量表，不更新或重建玩家、道侣关系和既有 operation。官方新静态种子按 `docs/release-distribution.md` 登记内容清单与规则文件的新旧 SHA-256、真实 Git 来源；仅缺失文件补齐，未识别的玩家自定义数据保留。

QQ 官方与 OneBot V11 通过同一 application、repository 和命令路由。适配器模拟可验证输入归一化与文本/动作结果，不等价于真实账号投递验收。
