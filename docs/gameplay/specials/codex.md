# 特色玩法：图鉴收集

图鉴记录玩家首次确认发现的世界事实：地点、材料、敌人、道途技艺、作物、商路、故事人物/结局和塔层首通。它提供长期收集与知识目标，不出售数值强度，不能成为修为或突破的替代来源。

## 1. 条目和发现

`specials.record_codex_discovery` 只能由白名单的已结算 operation 调用：地点到达、物品首次获得、敌人战斗结算、作物收获、派遣成功、塔层首通、竞技场首次对局、故事节点/结局确认。适配器和前端禁止直接“点亮”。

| `codex_category` | 首见来源 | 可显示内容 |
|:--|:--|:--|
| `place` | 成功到达地点 | 地点简介、开放版本、旅行提示 |
| `material` | 已结算获得物品 | 来源地区、用途标签、绑定说明 |
| `creature` | 战斗结算或观察派遣 | 敌人特征、技能摘要、图鉴编号 |
| `craft` | 学习配方或完成订单 | 配方方向、工具/设施提示 |
| `route` | 运输/派遣/探索结算 | 路线风险、贸易提示、发现版本 |
| `story` | 锁定节点/结局 | 已见文本摘要、不可逆选择说明 |
| `challenge` | 塔层首通/竞技场首次结算 | 战术记录、赛季/楼层历史 |

首次发现写不可变 `CodexEntry`（运行时表为 `codex_entries`）；后续同条目只更新最近查看时间，不能覆盖首见来源。隐藏条目只返回 `unknown` 和允许的提示，不泄漏未来内容/敌人/故事选择。

竞技场结算由服务端把参与、胜利/落败/平局分别投影为 `challenge` 类条目，并同步写入
`activity_events`。投影使用对局 operation 和 `(match_id, player_id)` 唯一约束；重复结算只回放，
不会重复创建图鉴或名望。

## 2. 集合里程碑

集合奖励按 `milestone_key + player_id + content_version` 唯一，只能是下列之一：地区名望、服务信誉、配方线索、路线提示、居所/设施外观、故事节点可见性或受限服务资格。禁止灵石大额包、修为、突破丹、战斗属性、跨境资格、道果和飞升功勋。

| 里程碑示例 | 条件 | 奖励 |
|:--|:--|:--|
| `codex.xuantian.materials_5` | 玄天材料 5 条 | 城镇名望 +5、`hint.herb_route` |
| `codex.town_services_3` | 城镇服务/路线 3 条 | 服务信誉 +3、运输委托额外展示 1 条 |
| `codex.paths_6` | 六道途首见 | 道途百科页解锁，不给属性 |
| `codex.mist_challenge_10` | 试炼塔 10 层记录 | 塔路线提示、展示徽记 |

图鉴预览/搜索是只读，不创建 operation。领取里程碑时需要 `operation_id`，并固定已满足条目集合快照。

## 3. 隐私、关闭与验收

图鉴默认只显示玩家自己的首见；竞技场对手名称/平台身份只显示脱敏名，故事私密结局不进入公共图鉴。内容关闭后旧条目仍可读，不能再发现/领取新版本条目。

验收：同一来源重放不双建条目；伪造前端条目拒绝；隐藏内容不泄漏；集合奖励唯一且不含战斗/修为收益；版本变更不改历史首见；管理员修复只追加审计说明。
