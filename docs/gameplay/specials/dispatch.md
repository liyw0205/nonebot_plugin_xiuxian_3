# 特色玩法：派遣任务

派遣是角色亲自或带领固定 NPC 合同执行的异步任务，不与玩家在线队伍、挂机、生产订单或探索会话共享状态。它以材料、货币、名望、信誉、图鉴发现和故事旗标为主产出；不得直接结算修为、跨境突破资格或永久战斗属性。

## 1. 派遣配置与风险

`specials.accept_dispatch` 输入任务键、可选承接配置（工具/合同物/角色路线）和 `operation_id`。扩展内容可定义可选配置；v0.1 只接受任务键。任务开始时冻结任务要求、角色层数、道途、设施/工具、成本、风险池、结束时间和奖励表；之后角色改装备、地点、道途、名望或内容版本不改变本任务结果。

| 字段 | 约束 |
|:--|:--|
| `dispatch_key` | 稳定键；发布后不复用 |
| `duration` | 10 分钟–12 小时；服务端时间 |
| `slots` | 每角色默认 1；不能与挂机/互斥会话并行 |
| `cost` | 体力、精力、材料、合同物或灵石；预检查失败零变化 |
| `risk_pool` | `none` 或确定性权重池；开始时保存实际抽取 |
| `output` | 物品、灵石、名望、信誉、图鉴/故事事件；禁止修为/突破资源 |
| `failure` | 返还、损耗、延迟或低收益；不能无记录吞资产 |

状态：`accepted -> running -> succeeded/failed -> settled`。接受即冻结风险结果、奖励、成本、快照与服务端开始/结束时间；`accepted` 仅有 60 秒确认窗口可取消并解锁，窗口到期进入 `running`；`running` 后不得取消。取消仍计入任务每日接受配额，避免用取消重抽风险。超过结束时间 24h 由恢复任务结算；已抽取风险不重抽。

## 2. 结果与损耗

风险结果仅四类：

1. `success`：获得完整输出。
2. `delayed`：结束时间 +50%，输出不变；仅首次抽取可进入。
3. `partial`：发放 50% 向下取整的堆叠产出；名望/信誉减半。
4. `failed`：不发输出；返还内容定义的未消耗材料，工具耐久最多 -300 bp。

`delayed` 只延长结束时间，不重抽结果；具体延长量由任务内容定义。`partial` 对堆叠物品按数量向下取整减半，名望/信誉减半；非堆叠图鉴/故事事件不因 partial 自动发放。

派遣不会造成装备永久丢失、境界下降、扣除未参与者资产或自动触发跨界战斗。高风险任务可消耗保险合同；保险只把 `failed` 转为 `partial`，不提高 success 权重。

## 3. 与其它玩法关系

- 派遣可消耗常驻经营的合同物、工具或设施资格，但不占用地块/居所。
- 派遣可获得图鉴线索或解锁故事节点，但不能直接完成图鉴里程碑或故事结局。
- 派遣可给 `local.*` 名望与服务信誉；不得给阵营战斗加成或突破准备度。
- 派遣首通/周常额度通过 `dispatch_key + player_id + window_key` 唯一约束。

## 4. 观测、关闭与验收

记录任务、角色/层数/构筑快照、成本、风险池/结果、开始/结束、返还、耐久、输出、版本和 operation。内容关闭停止新接受，running 会话按快照结算或恢复；不能以关闭为由没收锁定成本。

验收：并发只创建一条相同槽位任务；不同输入复用 operation 冲突；延误只能一次；失败按定义返还；保险不改变随机池；奖励没有修为/突破/终局资源；恢复结算与手动结算一致。

## 5. v0.1 运行时

文本入口：`派遣预览 [任务键]`、`接受派遣 <任务键>`、`取消派遣 [派遣编号]`、`结算派遣 [派遣编号]`；`开始派遣` 是接受命令别名。数值和风险权重以 [v0.1 特色玩法内容基线](content-v0.1.md#2-派遣任务) 为准。

接受时立即扣除成本、生成并持久化风险结果与奖励，服务端结束时间从接受时起算。60 秒内取消全额返还，但仍占用当日任务接受次数；超过窗口自动视为运行中。延误时长为原时长的 150%。失败返还仅按任务定义执行：药材搜寻返 2 体力，作坊帮工返 1 木材。派遣和挂机、探索、移动、修炼、生产、突破、战斗会话共用长时行动互斥。

runtime 初始化后每分钟扫描一次超过结束时间 24 小时的会话，并使用稳定恢复 operation 自动结算；失败会记日志并在后续周期重试。手动结算与后台恢复共用结算事务和来源 operation，派遣结算会写入 `specials.dispatch.settled`，供七日入道 D6、首次派遣功业和派遣称号读取。后台任务不会在 `runtime.close()` 后继续运行。
