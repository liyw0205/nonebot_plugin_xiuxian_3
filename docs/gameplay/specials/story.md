# 特色玩法：多结局剧情线

剧情线是版本化的节点图，不是一次性文本发送。玩家通过探索、图鉴、派遣、服务、塔层、阵营和明确选择推进；关键旗标和选择以不可变 operation 写入。故事结局可影响地点/服务/剧情可见性和地区名望，但不得直接把玩家送入高境界、授予突破概率或篡改飞升终局。

## 1. 节点和选择

每个故事定义：`story_key`、章节/节点键、开放条件、展示文本键、选择键、成本、条件快照、输出旗标、后继节点、结局键、版本和关闭策略。`specials.start_story` 创建 `StoryRun`；`specials.choose_story_node` 只接受当前节点的白名单选择键和 `operation_id`。

| 节点状态 | 含义 | 写入 |
|:--|:--|:--|
| `available` | 前置满足，尚未开始 | 无资产写入 |
| `active` | 节点文本/可选动作可读 | 运行记录 |
| `awaiting_choice` | 必须选一个锁定选项 | 条件快照 |
| `ending_pending` | 已达结局，允许领一次结局包 | 结局键/旗标 |
| `ended/expired` | 已结算或过期 | 只读 |

选择成本先预检查，成功时在同一事务锁/消费成本、写旗标、推进节点。若节点因时间窗过期，按定义走默认选择或 `expired`，必须显示原因；不能静默替玩家选高价值分支。

## 2. 多结局与资源边界

结局按 `story_key + ending_key + player_id` 唯一。允许输出：地区/阵营名望、图鉴条目、地点/派遣/服务/配方线索可见性、居所外观、展示称号、受限公共建设资格。禁止输出：修为、突破材料、跨境突破许可、永久战斗属性、道果、飞升功勋、直接结算 `ending_state`。

故事可读取（不能写）既有旗标：道途、地区名望、图鉴、塔层、派遣、竞技场积分段、关系与探索来源。结局之间可以互斥，如 `story.xuantian.road` 的 `merchant`/`warden`/`wanderer`；冲突选择必须由同一运行记录拒绝，不能新开相同故事绕过。

v0.6 的飞升/留界仍由 `ascension.choose_ending` 结算。故事结局最多提供该用例可读的“已见世界线”旗标，且只在终局开始前锁定；不能替代三次天劫、道果进度或最终战。

## 3. 隐私、恢复与验收

剧情文本与私密旗标默认仅玩家可见；公共展示只允许玩家显式选择公开的结局标题。恢复时以 `StoryRun` 中锁定节点、旗标、条件和版本为准，不因当前名望/装备/内容调整重算旧选择。

验收：无法直接跳到结局；选择重试返回同一节点/旗标；互斥结局不能共存；时间窗默认分支可审计；结局奖励唯一且不含修为/突破/终局资源；飞升用例只读取允许旗标，不接受故事写入终局状态。
