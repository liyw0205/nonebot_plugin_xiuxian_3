# 世界域：移动状态机

```text
travel: created -> running -> arrived
                    \-> interrupted/expired/failed
location: locked -> open -> closed
```

云舟使用独立 `cloud_boat_sessions` 会话，状态为 `created/running/arrived/failed/expired`。
云舟航线在创建时冻结来源、终点、费用和凭证；洞天二层和
深渊门不能通过普通 `travel_sessions` 直达。已运行航线到期后由结算/恢复按快照抵达，不随机
失事，不重复扣费。魔界引导和阵堂权限是独立 operation，失败不泄露生产结果。

妖界史阅读单独记录任务事件；完成妖界引导在一个事务中校验筑基、本人阅读事件、本人已结算的近郊探索和灵石，再写入入口权限、声望、任务事件与进度。万兽山预览和移动事务共用声望 `>=200` 或引导权限的准入规则，元婴门槛保持不变。

v0.5 虚空航道使用独立 `void_route_sessions` 会话。`结算虚空航道` 在发放航道奖励的同一事务
把 `players.location_key` 更新为航道键（例如 `void.archive_ruins`），并将抵达位置写入
operation 结果；重复结算只回放原结果。下游地点准入因此只能消费真实航道抵达证据，不能依赖
手工改写角色位置。

炼虚及更高境界可按炼虚准入线重新进入虚空航道；化神角色仍须完成三次界壁试炼才能进入
档案遗迹，其他虚空路线不因此向未达炼虚的角色开放。虚空堡垒还要求有效 5 级宗门成员身份，
虚空集市还要求虚空功勋达到 1,000。新建航道会话冻结创建时的准入与费用，
已创建会话继续按原快照结算。
云舟与虚空航道的稳定键、别名和数值分别由 `data/地图/云舟航线.json`、`data/地图/虚空航线.json` 提供；虚空风暴概率、
不稳定时长及锚费修正仍由既有共享规则裁决。地点 `travel.anchor_min/max` 当前没有运行时消费者，本次普通移动审计不将其接入虚空会话。

普通移动从 `区域.json` 按角色当前位置选择唯一有向边，读取该边的耗时、体力、灵石、通行物、每日启程上限和 typed
准入；同时校验目的地点的共同门槛。地图允许方向不对称，反向移动必须有自己的边。缺少路线时预览标记来源不匹配，启程
返回 `TRAVEL_ROUTE_INVALID`；道源门、天劫台和结局入口保留各自既有领域错误码。地点和其所属区域只有 `active/open` 才
可启程。

迁移后的旧路线仍按旧运行时的目标地点费用结算：旧地点记录或目的地规则已有费用的，写回全部对应入边；两端旧规则皆无费用的
新地点继续免费。边成为当前权威不等于价格调整。地点共同门槛适用于每次抵达该地点；边上的门槛只对那一个方向生效。
洞天二层和深渊门虽保留地图关系，仍须使用云舟领域的专用路线；地图边费用不替代云舟航费。

同一事务在 operation 历史结果核对后、费用锁定前执行来源/路线/地点/门槛/资源/并发检查；抵达结算才写入新位置。普通路线
通行物默认启程时扣除，边显式设置 `consume_pass_on_arrival=true` 时在抵达事务扣除；新会话冻结实际路线成本和扣除时点。
旧 operation 重放与已开始行程结算不查询现行地图，分别以账本和原会话快照为准。云舟和虚空航道继续使用各自独立的路线
准入与会话。

跨界地点的阵营声望在预览阶段展示缺口，并在开始事务内重新读取并原子校验；不足时不得扣除体力或灵石。
开始成功后，移动会话快照必须保存阵营、所需声望和开始时声望值，
后续结算不得因现行内容或角色声望变化改写已开始的准入结果。

普通路线通行物默认在会话创建时扣除；只有路线边显式声明抵达扣除时，才在位置更新的同一事务扣除。抵达时凭证不足必须
整笔回滚，保留 `running` 状态和原位置；成功结算写入 `arrived`，重复 operation 只回放原结果。终局战托管的
`item.ascension_certificate` 由终局战结算，不作为飞升路普通移动的二次凭证。

地点关闭不强制删除已在其中的角色；后续行动按撤离或封锁规则处理。重复到达结算只能写一次位置变更。

地图预览以当前来源的普通有向边为先；同一目标存在普通路线时，云舟的同目标航线不会误报成普通路线不可用。无普通入边的
云舟目标则展示专用航线、合法起航地点、云舟成本与缺失的任务/境界/资源条件。缺少参数时，云舟/虚空航道命令从当前开放内容列出选择名。旧云舟与虚空
航程 operation 重放先验证账本；已创建会话的完成/恢复仅读取快照，因此关闭或改动现行内容只影响新请求。
