## 3. 依赖与复用

```text
identity/player
  -> stats/resources/items
  -> progression/paths
  -> world/exploration
  -> combat/production
  -> social/economy/events
  -> routine/adventures/companions/specials
  -> content operations / web / external integration
```

原 P0–P8 是工程能力与风险阶段，已有基础不重复重建；Web/支付/跨服依赖不自动变成
开放入口。按真实依赖选择队列最高优先级可开工项；同一缺口可以跨域闭合，
不靠目录轮转、十条冷却统计或重复共享工具整理决定工作。

复用现有 application、领域 repository、persistence/UoW/ledger 和 utils。
背包、灵石、角色状态变更与资料/战斗归一化使用现有共享内核；不复制领域事务、
资产序列化、奖励表或适配器业务逻辑。战斗服务端自动选择行动和目标，客户端
不能提交攻击、技能、目标、伤害或结算；训练傀儡和直接切磋继续只读观战。

## 4. 一条任务的交付模板

开工前在唯一队列登记：合同引用、当前缺口/复现、依赖、入口、文件所有权、验收范围
和明确退出条件。合同不足则登记具体问题，先补合同，入口继续关闭。
只有明确授权且有独立文件边界时安排子代理；不重复启动相同审计或长测试。

交付须说明：

- 玩家入口、权限、消息降级、固定文案与领域合同。
- 实体/不变量/状态机，前置、成本、产出、随机、配额、失败/取消/过期。
- DTO/application owner、operation 输入指纹与重放、并发锁、UoW/流水和故障回滚。
- JSON 来源、稳定键/引用、实际消费、冻结业务数值与结果；不新增运行时版本字段。
- 数据库结构变更、备份恢复、关闭新建、已有会话处理与回滚。
- 受影响测试、结果、skip/未覆盖项和验证基线；触发统一见[测试策略](testing.md)。

不在每条任务重新验证所有未触及领域；同一证据仍有效时复用，写明适用范围。

## 5. 内容调整与回滚

产品边界/跨域依赖先更新总表，实体与流程更新领域合同，可调参数更新现行 JSON
和消费测试。使用整数/万分比及确定性时钟/随机端口，不在 Python 保留同义内容表、
静默默认值、规则版本分支或旧格式兼容。

已结算 operation 与在途业务只读原冻结快照，不因内容改名、关闭或改值重新计算。
回滚优先关闭新建，保留账本、资产流水与已有会话；数据库/用户数据不得自动清理。
缓存/临时产物清理遵守[运行规范](operations.md#6-开发产物与缓存清理)。
