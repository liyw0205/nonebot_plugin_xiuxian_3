# 有限阶段规划模板

本文定义如何把一个明确需求收敛成可验收的有限阶段，不记录当前分支队列、候选任务或阶段完成流水。完整玩法范围由[内容设计总表](content-development.md)和领域合同裁决；状态边界见[运行能力状态判定](current-status.md)。

## 范围与退出条件

每个阶段开工前写清：

- 当前玩家入口和可复现的缺口，或新入口的明确需求。
- 适用的产品/领域合同、依赖数据与既有消费者。
- 本阶段涉及的用户流程、文件所有权和明确不包含的范围。
- 业务状态变化、资产来源、奖励去向及失败/取消/重试语义。
- 定向测试、需要复用的既有证据和阶段退出条件。

退出条件应能通过结果验证，而不是“完成代码”或“更新文档”。内容阶段至少闭合公开取得来源、准入、实际消费、结算与后续状态；异步或持久化阶段还需覆盖快照、重启、幂等和恢复。锁定内容、外部平台或发布条件单独列明，不用来掩盖本地开放流程的缺口。

## 依赖与实现顺序

```text
角色/身份
  -> 属性、资源与物品
  -> 境界、道途与世界
  -> 探索、战斗与生产
  -> 生活、经济、社交与活动
  -> 剧情、特色玩法与外部接入
```

依赖图用于选择实施顺序，不要求按目录轮转。先追踪现有入口到 application、领域服务、repository 和持久化，再确认数据由哪个消费者读取；跨入口功能复用同一用例，不在适配器中复制业务规则。

## 交付与回滚

一项交付至少说明入口/权限、前置/成本/产出、状态机、随机与快照、operation 幂等、事务边界、并发/唯一约束、错误与恢复，以及受影响测试。静态内容须验证稳定键、引用、可达来源和真实消费者；官方种子指纹与迁移遵守[发布分发约定](release-distribution.md)。

回滚优先关闭新建并保留已结算流水、玩家资产及在途会话的原始快照。数据库和用户数据不得通过删库重建恢复；缓存与临时产物只清理已确认属于当前任务的文件。

测试范围按[测试与验收](testing.md)选择。完成后更新长期有效的玩家说明和领域合同；运行队列、分支/CI 状态及临时环境证据不写入发布文档。
