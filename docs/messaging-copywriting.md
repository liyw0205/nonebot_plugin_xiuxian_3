# 消息与文案规范

角色命令的 `CommandResult.message` 统一按 Markdown 编写。消息要先告诉玩家发生了
什么，再展示少量关键资料，最后给出一个明确的下一步；不要把内部模块名、异常堆栈、
数据库字段或实现说明直接展示给玩家。

## 格式

- 使用 `##` 作为一次命令结果的标题。
- 使用项目符号列出道号、阶段、位置、灵石和资质等字段。
- 道号和重要结果使用粗体；内部 ID、稳定键和数据库字段不对玩家展示。
- 下一步使用引用块 `>`，一次只推荐一个动作。
- 资质、奖励等同类数据分组展示，避免把内容挤在一行；阶段、状态、位置和资质名称使用中文文案。

## 适配器行为

- QQ 适配器使用 QQ 原生 Markdown 消息段。
- OneBot V11 不发送 QQ 消息段，自动移除 Markdown 标记后发送普通文本。
- 未声明 Markdown 能力的适配器同样退化为普通文本。
- 消息格式失败只影响展示，不得回滚或重复执行角色 operation。

## 当前命令示例

`开始修仙`、`寻仙问道`、`完成引导`、`前往近郊`、`返回新手城`、`选择道途`、`修仙改名`
和 `我的状态` 的成功结果都遵守上述结构；修炼循环还包括 `开始修炼`、`结算修炼`、
`开始修炼 灵泉`、`结算修炼`、`恢复修炼`、`取消修炼`、`晋升境界` 和 `恢复状态`。
`我的修仙信息` 是 `我的状态` 的别名。用户可见资料使用道号，不展示平台用户 ID；
未取道号时显示“未命名”。错误消息保持简短，只说明原因和可执行的修复动作。

灵泉谷入口使用 `前往灵泉谷`。成功时说明抵达地点和剩余体力；灵泉修炼成功时说明
15 分钟时长、3 点体力、基础修为 70 和每日剩余次数。准入不足、位置不符或当日次数
用尽时，只展示中文原因和可执行的下一步，不展示地点键、模式键或规则版本。

## 引导与入道示例

```markdown
## 教学采集完成

**未命名**，你在玄天近郊采得 **止血草 ×2**。

- **体力**：26/30
- **引导进度**：2/3

> 下一步：`完成引导 炼丹`、`完成引导 炼器` 或 `完成引导 布阵`
```

```markdown
## 入道完成

**青云**已选择 **体修**，正式踏入修行之路。

- **境界**：感气一层
- **灵石**：300
- **入道所得**：基础功法与对应试用技能

> 下一步：查看 `我的状态`
```

```markdown
## 修炼结算完成

**青云**获得 **修为 ×42**。

- **境界**：感气 L1
- **境内修为**：42/80
- **总修为**：42
- **体力**：28/30

> 下一步：继续发送 `开始修炼`，积累境内修为。
```

```markdown
## 过期修炼已恢复

**青云**按原始修炼快照完成了迟到结算。

- **恢复修为**：42
- **境界**：感气 L1
- **境内修为**：42/80
- **总修为**：42

> 这场修炼只会恢复结算一次；达到门槛后可发送 `晋升境界`。
```

```markdown
## 灵泉修炼已开始

**青云**已在灵泉谷开始灵泉修炼。

- **消耗体力**：3
- **剩余体力**：25/30
- **预计时长**：15 分钟
- **今日灵泉次数**：1/4

> 下一步：15 分钟后发送 `结算修炼`。
```

晋层命中 L3、L6、L9 或 L10 时，在基础结果后追加 `### 本层解锁` 列表。列表只展示
已实现资格或未来玩法预览，不展示稳定键，也不把预览写成已经开放的功能。
