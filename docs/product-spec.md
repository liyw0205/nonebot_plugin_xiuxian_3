# 产品规格

## 1. 产品定位

这是一个运行在 QQ 群、QQ 私聊和频道场景中的异步文字修仙游戏。玩家以
账号为主体，积累修为与资源，学习功法、探索世界、参与战斗和社交活动；
服主通过 Web 面板管理配置、数据、任务和运行状态。

“兼容”只表示玩家仍能使用已发布的命令、别名、权限和关键结果。新项目
不承诺复刻旧项目的内部类、数据库表、随机数实现或消息排版细节。

## 2. 用户角色

| 角色 | 目标 | 需要的能力 |
|:--|:--|:--|
| 玩家 | 成长、战斗、收集、社交 | 命令、按钮、状态卡、个人数据 |
| 群管理员 | 管理本群体验 | 群配置、屏蔽、广播、权限范围内的运营操作 |
| 服主 | 保持服务稳定 | Web 管理、备份、恢复、任务、日志、更新 |
| 开发者 | 增加玩法而不破坏旧玩法 | 领域用例、端口、manifest、迁移和测试模板 |

## 3. 核心游戏循环

1. 玩家创建或恢复角色，选择灵根/初始方向并查看状态。
2. 通过修炼、历练、悬赏、地图探索和活动获得修为、灵石、物品与声望。
3. 学习功法和神通，装备法器、防具、饰品，培养宠物与洞府。
4. 进行突破、渡劫、PVE/PVP、秘境、副本、通天塔和世界事件。
5. 通过宗门、师徒、道侣、传功、交易和拍卖形成长期社交与经济循环。
6. 每日/每周任务、签到、重置和赛季奖励提供周期性回访。

所有循环都必须明确：前置条件、消耗、随机性、冷却、失败结果、奖励、
重复请求语义和管理员可观测字段。

## 4. 功能边界

### 4.1 首要玩法

- 角色与状态：注册、改名、等级/境界、修为、灵石、体力、冷却和状态卡。
- 修炼与突破：普通修炼、连续修炼、炼体、窍穴、突破、渡劫和失败保护。
- 物品与成长：背包、功法/辅修/神通/身法/瞳术、装备、丹药、炼丹、合成、
  礼包、聚灵旗、称号和增益。
- 世界活动：地图移动、探索、资源点、悬赏、秘境、秘境令、副本、裂隙、
  世界 Boss、魔修入侵和活动领奖。
- 战斗：普通 PVE、Boss、宗门/道场战斗、竞技场、天梯、切磋/PK、战斗结算。

### 4.2 社交玩法

- 宗门：创建/加入/退出、职位、贡献、任务、材料、宗门领地和日常重置。
- 关系：师徒申请与绑定、道侣邀请与保护、传功/双修、关系解除与奖励。
- 互动：问候、每日运势、赠送灵石、祈愿、抽奖、小游戏和群内广播。

### 4.3 经济与运营

- 银行：存取、利息、等级和周期结算。
- 交易：鬼市存取、寄售、现世购买、拍卖场次、竞价、收尾和过期清理。
- 管理：玩家/物品/灵石/经验调整，黑屋，补偿，数据修复，备份、恢复、
  更新和任务控制。
- Web：配置、消息记录、数据库只读/受控写入、任务、日志、备份、奖励中心。

### 4.4 娱乐扩展

- 链接与媒体解析、图片/音频/视频发送、每日资讯和番剧。
- WebDAV 账号与文件浏览、NewAPI 绑定/签到、小游戏、随机内容和互动图片。

娱乐扩展必须与核心经济隔离；外部网络失败不能破坏玩家资产事务。

## 5. 不在首版承诺的内容

- 不承诺完全复刻旧项目的数值、随机种子、图片模板或数据库物理布局。
- 不在首个可玩版本同时迁移所有历史数据；迁移以可验证的领域切片推进。
- 不允许把管理员 Web 面板直接暴露到公网而不启用会话、CSRF 和 Host 校验。
- 不把娱乐外部服务的可用性当作核心游戏的健康条件。

## 6. 产品验收原则

一项功能只有在以下条件同时满足时才算完成：命令/按钮流程可用、失败路径
有明确提示、资产变化可审计、重复请求不重复结算、跨适配器语义一致、隔离
数据目录测试通过、必要时可从备份恢复，并且文档中的操作契约与实现一致。
