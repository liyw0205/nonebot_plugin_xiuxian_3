# 上游参考与复用边界

## 1. 参考来源

上游仓库：

`https://github.com/liyw0205/nonebot_plugin_xiuxian_2_pmv`

本项目使用上游公开文档作为两类参考：

1. 从 `README.md`、`gameplay_notes.md`、`buff.md` 和 `items.md` 提取通用玩法分类与玩家流程。
2. 从 `adapter_compat.md`、`on_compat.md`、`message_channel.md`、`database_web_governance.md` 和 `web_panel.md` 提取适配器兼容、消息投递、路由、Web 安全和运行治理经验。

## 2. 可以参考的通用玩法

上游文档证明以下类型适合文字修仙插件，但不规定修仙 3 的具体实现：

- 修炼、突破、境界成长和状态查询。
- 地图、探索、采集、悬赏、秘境、世界事件和限次玩法。
- 功法、辅修、神通、身法、瞳术、法器、防具、丹药、材料和特殊道具。
- 洞天福地、灵田、聚灵、炼丹和资源生产。
- 宗门、师徒、道侣、传功、队伍、委托和玩家协作。
- 灵石、市场、摆摊、拍卖、礼包、补偿和周期活动。
- 宠物、称号、成就和排行等可能的文字游戏模块。

修仙 3 将可采纳的内容重新映射到自己的公共境界、六大道途、辅修体系和三界世界观。媒体、WebDAV、第三方账号、小游戏和娱乐积分不属于修仙3范围，不能以“隔离扩展”名义重新加入。上游玩法只是说明“哪些玩法类型值得考虑”，不直接提供境界、倍率、概率、物品名、命令或数据库结构。

## 3. 可以复用的适配器经验

上游魔改适配器兼容层的以下思路可以在修仙 3 中复用，优先作为设计参考，必要时复用成熟实现：

- 将 OneBot V11、QQ 官方适配器和频道事件归一为统一场景：群聊、私聊、频道群、频道私信。
- 统一事件字段：用户 ID、群/频道 ID、消息 ID、纯文本、发送者、引用 ID、是否指向机器人。
- 统一消息段构造：文本、图片、音频、视频、文件、Markdown、键盘和引用回复。
- 用投递门面隔离主动群发、私聊、回复、撤回、消息记录和广播。
- 对 QQ 的 `REFIDX`、`msg_seq`、interaction ACK、媒体上传和能力差异做平台侧处理。
- 在空前缀或大量命令场景下使用命令/前缀索引减少无效 matcher 检查，同时保留通用 `on_message` 和无法安全分析的正则。
- 对 Markdown、键盘、媒体和引用回复提供能力检测与纯文本降级。
- 将消息记录、撤回、广播、限流、事件去重和任务队列做成独立模块。
- Web、消息和业务用例共用应用层，不在 Web 路由中复制资产规则。

这些能力属于适配器和基础设施边界，不应反向决定修仙 3 的玩法。

## 4. 明确禁止直接继承的内容

以下内容不作为修仙 3 设计依据：

- 上游境界名称、等级编号、修为需求和所有倍率。
- 上游功法、神通、装备、丹药、宠物、礼包和物品 ID。
- 上游命令名称、别名、帮助列表和消息模板。
- 上游 SQLite 表结构、JSON 字段、旧数据兼容逻辑和历史脏数据修复方案。
- 上游玩法中的具体抽奖池、掉落表、概率、排行榜和经济数值。
- 直接复制上游业务模块、领域对象、数据库文件或运行数据。

如果某项旧行为未来确实值得保留，必须先转写成修仙 3 的产品规则，再由新领域用例实现。

## 5. 适配器源码复用规则

适配器可以复用上游魔改兼容层的工程实现，但必须满足：

1. 先确认许可证、来源版本和本地修改范围。
2. 适配器代码放在 `src/xiuxian3/adapters/` 或明确的 vendored 命名空间，不混入领域层。
3. 对外只暴露修仙 3 的统一 `CommandContext`、`ReplyPlan`、`MessageCapability` 和 `DeliveryResult`。
4. 上游接口名、旧模块路径和旧业务依赖不能扩散到 application/domain。
5. 复用后必须补 OneBot/QQ/频道 fixture、能力降级、引用回复、重复事件和失败发送测试。
6. 上游适配器升级时记录上游 commit/tag、许可证、差异和回归结果。

## 6. 参考证据等级

- A：上游公开文档明确描述的稳定行为或适配器约定。
- B：上游文档中的玩法分类，可用于发现功能方向。
- C：需要从上游运行时或代码推断的细节，只能作为调查线索。
- D：上游具体数值、旧命令、旧表结构和单个 bug 修复，不得自动进入修仙 3。

## 7. 修仙 3 的裁决原则

当本文件与上游行为冲突时，以 `xiuxian3-design.md` 和对应子文档为准；当玩法文档与适配器文档冲突时，玩法规则优先保持平台无关，适配器负责降级和呈现。
