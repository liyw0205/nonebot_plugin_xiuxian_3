# 外部参考与来源管理

外部项目、协议文档和开源实现可以提供调查线索，但不能替代本项目的产品规则、运行时证据或数据合同。引用外部资料时，先验证其适用范围，再把需要的规则转写为本项目自己的稳定键、领域模型、命令和测试。

## 玩法与数据

- 通用玩法分类可用于发现设计方向；境界、数值、概率、物品 ID、命令、奖励表和数据库结构必须由本项目的产品规则裁决。
- 不因外部资料存在某种功能，就推断该功能属于本项目范围或已在运行时开放。
- 不复制外部玩家数据、业务模块、资产文件或旧格式兼容逻辑。确需迁移时，先定义来源、授权、数据映射和可回滚步骤。

## 第三方代码与依赖

- 使用或分发第三方代码前核实来源版本、许可证、依赖约束和本地修改范围。
- 分发的第三方源码须保留许可证与来源说明，并置于清晰隔离的命名空间；不得直接修改虚拟环境中的安装文件。
- 当前运行来源以实际宿主解释器加载的发行包、版本和模块路径为准。仓库没有对应源码时，不得把外部依赖行为描述成仓库内已实现。
- 适配器只处理平台事件、权限上下文和结果呈现；平台对象不得进入 application 或领域层。

SDK 来源确认、变更评估和适配器边界见[适配器运行时来源与升级核验](adapter-upstream-review.md)。
