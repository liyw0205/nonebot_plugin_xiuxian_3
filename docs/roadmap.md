# 开发路线

路线从空仓库开始，每一阶段都要求可运行、可测试、可回滚；不要先搭一个巨大
框架再把所有玩法一次性塞入。

## P0：基线与规则冻结

- 固定参考主分支提交、命令/别名/权限/帮助清单和外部入口。
- 写出数值、随机、时间窗口、失败和幂等的验收样例。
- 建立依赖、Python 版本、测试命令、隔离数据目录和安全扫描。

完成标志：规格评审通过，任何行为差异都有记录，不复制旧实现文件。

## P1：最小运行时

- 构建配置、路径、日志、时钟、随机、ID 和生命周期端口。
- 建立 NoneBot 插件入口、manifest 注册表、健康检查和空 feature。
- 建立统一结果/错误/operation 模型。

## P2：数据与消息基础设施

- SQLite 连接/UoW、迁移器、操作流水、备份和恢复。
- OneBot/QQ 事件归一化、消息投递、限流、去重和能力降级。
- Web 登录、权限、CSRF、统一 envelope 和只读健康页。

## P3：首个可玩闭环

按“注册/信息 → 签到 → 修炼 → 状态查询”实现一个完整垂直切片，包含命令、
按钮、应用用例、迁移、审计、隔离测试和跨适配器冒烟。此阶段不接复杂战斗。

## P4：基础成长与物品

实现背包、物品定义、技能/装备、丹药、炼丹、合成、突破和炼体。先建立稳定
数值/随机版本，再逐步导入数据资源；历史 JSON 仅作为导入源，不成为领域依赖。

## P5：世界、战斗与社交

依次实现地图/探索、秘境/副本、Boss/世界事件、宗门、师徒/道侣、宠物、洞府、
竞技场/天梯/通天塔。每项从单人状态机开始，再加入多人并发和奖励结算。

## P6：经济与活动

实现灵庄、鬼市/仙肆、拍卖、活动、任务、补偿、邀请和赛季。所有交易先锁定
资产、再结算、再清理；完成失败恢复和重复请求演练后才开放真实数据迁移。

## P7：Web 运维与娱乐

补齐配置、数据库受控编辑、消息、奖励中心、任务、日志、备份、更新和审计页；
再接入媒体、WebDAV、NewAPI、番剧和小游戏等可选外部能力。

## P8：兼容发布与清理

- 将旧命令/别名和历史数据通过显式 shim 接入。
- 运行至少一个完整发布周期，观察兼容命中、资产流水和恢复指标。
- 满足“无命中、迁移完成、备份可恢复、文档更新”的条件后删除 shim。

## 每阶段交付物

功能文档、ADR（若有决策）、manifest、领域/应用代码、迁移、适配器、测试、
观测指标、运行说明和回滚步骤必须在同一个变更中更新。未具备回滚路径的资产
功能不得进入默认开启状态。
