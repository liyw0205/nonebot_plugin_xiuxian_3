# 测试策略

## 1. 测试分层

| 层级 | 内容 | 运行条件 |
|:--|:--|:--|
| 领域单元 | 数值、状态机、冷却、随机池、权限和不变量 | 不需要 NoneBot、数据库或网络 |
| 应用集成 | 仓储、事务、幂等、迁移、失败回滚 | 临时 SQLite/文件目录 |
| 适配器契约 | OneBot/QQ 事件归一化、消息段和能力降级 | 固定事件 fixture，无真实凭据 |
| Web 契约 | 权限、CSRF、DTO、错误 envelope、路径边界 | Flask/ASGI 测试 client |
| 任务与恢复 | 任务注册、重试、锁、备份恢复、操作重放 | 隔离进程或临时目录 |
| 端到端冒烟 | 注册→修炼→奖励→查询；管理员配置/备份 | 本地测试 Bot 或模拟适配器 |

## 2. 每个垂直切片的最低用例

每个资产功能至少覆盖：成功一次、重复 operation、参数无效、权限不足、
冷却/次数、资源不足、容量不足、状态冲突、随机结果记录、仓储异常回滚、
任务重试和适配器文本/按钮两条入口。读功能至少覆盖空数据、脏数据和权限。

## 3. 发布门槛

- 静态检查、类型检查和单元测试通过。
- 迁移在空库、旧快照和重复执行三种状态通过。
- 运行两次启动，命令/任务/监听器数量不增加。
- 关键 operation 重放结果一致，资产流水只有一条。
- OneBot 与 QQ 官方适配器各完成最小命令和媒体降级冒烟。
- Web 写路由拒绝无会话、无 CSRF、越权、非法路径和重复请求。
- 备份恢复演练有可重放记录；日志不含 secret。

## 4. 测试数据纪律

测试必须设置独立数据根目录，不能读取或修改开发者的 `data/`、生产 SQLite、
浏览器状态、SSH 密钥、环境 token 或真实 QQ 身份。随机、时钟、ID 和外部 HTTP
全部通过端口替换为确定性 fake。
