# 测试策略

## 1. 测试分层

| 层级 | 内容 | 运行条件 |
|:--|:--|:--|
| 领域单元 | 数值、状态机、冷却、随机池、权限和不变量 | 不需要 NoneBot、数据库或网络 |
| 应用集成 | 仓储、事务、幂等、迁移、失败回滚 | 临时 SQLite/文件目录 |
| 适配器契约 | OneBot/QQ 事件归一化、消息段和能力降级 | 固定事件 fixture，无真实凭据 |
| Web 契约 | 权限、CSRF、DTO、错误 envelope、路径边界 | Flask/ASGI 测试 client |
| 任务与恢复 | 任务注册、重试、锁、备份恢复、操作重放 | 隔离进程或临时目录 |
| 端到端冒烟 | 注册→修炼→奖励→查询；管理员配置/备份 | 本地测试 Bot 或模拟适配器 |

## 2. 每个垂直切片的最低用例

每个资产功能至少覆盖：成功一次、重复 operation、参数无效、权限不足、
冷却/次数、资源不足、容量不足、状态冲突、随机结果记录、仓储异常回滚、
任务重试和适配器文本/按钮两条入口。读功能至少覆盖空数据、脏数据和权限。

## 3. 发布门槛

- 静态检查、类型检查和单元测试通过。
- 迁移在空库、旧快照和重复执行三种状态通过。
- 运行两次启动，命令/任务/监听器数量不增加。
- 关键 operation 重放结果一致，资产流水只有一条。
- OneBot 与 QQ 官方适配器各完成最小文本命令、按钮 ACK 与纯文本能力降级冒烟；修仙3不提供媒体/娱乐适配器。
- Web 写路由拒绝无会话、无 CSRF、越权、非法路径和重复请求。
- 备份恢复演练有可重放记录；日志不含 secret。

## 4. 测试数据纪律

测试必须设置独立数据根目录，不能读取或修改开发者的 `data/`、生产 SQLite、
浏览器状态、SSH 密钥、环境 token 或真实 QQ 身份。随机、时钟、ID 和外部 HTTP
全部通过端口替换为确定性 fake。

## 5. 文档与内容基线门槛

文档职责、阅读顺序和切片交付清单统一见[开发文档总入口](development-guide.md)。本节只保留
验证门槛，避免在测试策略中复制产品路线。

在进入新玩法代码前，以及修改任何 `content-v*.md`、设计总纲或实施计划后，必须：

本仓库的标准 Python 入口使用 `$HOME/myenv`：`$HOME/myenv/bin/python -m pytest -q`；
不要用系统 Python 代替，因为 QQ/OneBot fixture 依赖安装在该虚拟环境中。

1. 校验 `data/**/*.json` 的格式，运行 `$HOME/myenv/bin/python -m pytest -q`，并执行 `git diff --check`。内容合同、首版开放/占位边界、关键稳定键、跨域任务、终局可达性、十层境界、常驻经营、道历运营、冒险、养成、灵兽灵骑与上游隔离约束，以[完整内容开发总表](content-development.md)为审查清单；娱乐目录或娱乐内容包回归必须拒绝。
2. 检查 `docs/index.md`、`docs/xiuxian3-design.md`、`docs/implementation-plan.md`、`docs/current-status.md` 和对应域 `README.md` 都能定位到该功能的权威内容文件，并且没有把历史快照误写成当前运行时状态。
3. 对新增稳定键执行内容包 dry-run：每个消耗品有可达来源、每个配方产出有 `item.*` 定义、每个地点/突破前置有已发布或明确 locked 的任务定义；不得使用显示名代替稳定键。境界必须以 `realm_key + realm_layer` 表示，只有 L10 混元可跨境；常驻经营结算不得写修为/突破准备度。
4. 检查 [上游参考与复用边界](reference-sources.md) 中的禁止继承项仍然存在：上游境界、数值、命令、物品、表结构和业务模块不得成为新玩法默认来源。
5. 执行 `git diff --check`；文档与内容基线变更必须记录版本、经济影响（如有）和回滚说明。
6. 运行 `$HOME/myenv/bin/python -m pytest -q test/test_documentation.py`。该测试校验
   `README.md`、`CONTRIBUTING.md` 与 `docs/` 内的本地 Markdown 链接，入口文档重组后不得留下断链。

跨服宗门战专项验收位于 `test/test_sect_war_cross_server_v05.py`，覆盖 QQ 官方与 OneBot V11、堡垒建造/维护、30/15 名额、服务端自动战、分支锁定、来源 operation 反刷、公共奖励箱、周奖励幂等、并发建造和 7 日过期恢复。

联盟与信标专项验收位于 `test/test_sect_alliance_beacon_v05.py`，覆盖 QQ 官方与 OneBot V11、active 堡垒准入、24 小时信标建造、航道最低 1 锚折扣、联盟双确认/过期、每周 3 项研究上限、研究标记资产隔离、双确认解除、10000 违约费、冷却和 operation 幂等。

文档验证通过不等于玩法代码已经通过。若当前测试有未完成探索代码引起的失败，报告必须区分“文档门槛通过”和“工程测试未通过”，不得以文档检查掩盖代码回归。
