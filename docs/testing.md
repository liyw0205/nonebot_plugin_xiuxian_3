# 测试与验收

本页规定测试隔离、覆盖范围与证据表达。玩家可用能力见[当前可用能力](availability.md)；玩法内容和行为分别遵守[数据内容合同](content-data-contract.md)与[通用功能合同](content-development-contract.md)。

## 1. 环境与数据隔离

使用项目当前 Python 环境和已安装依赖。测试需要 NoneBot、QQ 或 OneBot 模块时，应在目标环境验证依赖；缺失的必要依赖不能用 skip 代替通过。

测试使用独立临时数据根目录、假身份、确定性时钟和随机种子。内容副本只包含静态内容，不带运行 SQLite、WAL/SHM、备份、本机身份或真实凭据。测试不得自动清空用户数据目录；清理仅限已确认归属的测试产物。

## 2. 按变更范围验证

| 变更 | 必要验证 | 扩大验证的条件 |
|:--|:--|:--|
| 文档 | 本地链接、文案/合同断言、`git diff --check` | 文档改变行为规则时验证对应实现与内容 |
| 单一领域代码 | 本域合同用例、直接调用方、受影响事务/适配器/恢复边界、编译 | 修改共享 DTO、仓储、资产、随机、快照或锁语义时加入调用域 |
| 静态内容 | JSON 解析、内容引用、来源、实际消费者、关闭与快照语义 | 跨领域引用变化时覆盖来源生产者和消费者 |
| 共用内核/持久化 | 所有受影响调用域、幂等/并发、回滚/恢复和迁移不变量 | 影响面无法界定或有未解决风险时运行更广验证 |
| 正式版本验收 | 项目定义的完整测试、安装升级/恢复、内容和平台合同 | 真实外部环境仅在具备对应条件时验收 |

测试覆盖改动影响的行为，不只覆盖新增成功路径。共享业务链经统一 application 验证；QQ、OneBot 等适配器验证输入归一化、消息能力和失败降级，不以模拟结果声称真实平台投递或客户端呈现。

## 3. 必要行为覆盖

资产写入至少覆盖成功、前置/权限不足、参数冲突、资源不足、重复 operation、同 ID 不同输入、随机重放、并发、数据库异常回滚、重试和重启恢复。内容矩阵还应验证坏引用、边界因子、无候选、权重变化和来源/消费者闭合。

只读功能覆盖空数据、损坏数据和权限边界。关闭新建不得破坏既有快照与合法 operation 回放；损坏快照或账本必须零写失败。内容检查须验证重复对象键、非有限数值、缺字段和坏引用，单独 JSON 语法检查不能替代严格内容验载。

## 4. 证据表达

记录实际命令、Python 入口、代码/内容基线、passed/failed/skipped 数量、skip 原因、未执行项和证据位置。文档测试、定向测试、全量测试、fixture/SDK 模拟、真实平台和完整玩家路径分别说明，不互相冒充。

失败时先定位环境、夹具或实现原因，并对真实失败作最小修复与回归；不得通过删除断言、降低阈值、禁用测试或把失败改为跳过来求通过。未完成、失败或组合复用的局部结果不得写成一次完整通过。

验证串行且资源有界。同一代码、内容和环境的已通过证据，在相关边界未变化且没有新失败时可复用；
仅补录文档不触发重复的完整成长链或全量测试。长测记录命令、会话与基线，只保留一份运行实例；
中止或超时须如实记为未完成。

真实 QQ 账号连接、按钮回调 ACK、Markdown/蓝字呈现及 OneBot 实际投递需要相应平台证据。没有对应账号、设备或环境时，应明确标为未验，不自动推断能力已开放或已投产。
