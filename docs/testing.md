# 测试策略

本页是测试触发、执行环境和结果记录的唯一规范；产品范围见
[完整内容总表](content-development.md)，工作与证据只登记[当前状态](current-status.md)。

## 1. 环境与数据隔离

远程开发/验收统一使用 `/root/myenv/bin/python`，不用系统 Python 或其他虚拟环境代替。
测试需 NoneBot/QQ/OneBot 时先确认该环境的依赖；缺依赖要修环境并补验，不能以 skip 冒充通过。

测试使用独立临时数据根目录与确定性随机、时钟、ID/HTTP fake。内容副本只带静态内容，
不能带入运行 SQLite、WAL/SHM、备份或本机身份；不读取用户数据、真实账号或凭据。
清理只限本次测试确认归属的产物；保护活跃 agent 目录、`/tmp/codex-daemon-*`、IPC/socket/lock，
禁止按通配符清空 `/tmp` 或数据目录，见[运行规范](operations.md#6-开发产物与缓存清理)。

## 2. 按变更选择验证

| 变更 | 每次必要验证 | 扩大验证的条件 |
|:--|:--|:--|
| 仅文档/开发入口/goal | 文档链接测试、`git diff --check`，人工核对唯一入口/职责/规则冲突 | 文档明确改变了玩法合同且需要对应实现时，按相关代码范围验证 |
| 单一领域代码 | 缺陷复现或合同用例、本域相关测试、直接调用方和受影响适配器/事务/恢复边界；编译与 diff | 改变公共 DTO、仓储/资产/随机/快照/锁语义则加入实际调用域；未解失败继续扩大 |
| 静态内容 | 消费路径、内容/JSON/引用/来源/随机/快照检查，加受影响领域 | 跨域来源/引用变化则加入相关生产者/消费者；纯新增记录不自动触发整仓长链 |
| 共用内核/持久化 | 受影响调用域、幂等并发与回滚/恢复、迁移不变量 | 影响无法用聚焦边界说明或有未知跨域回归时阶段性全量 |
| 发布里程碑/重大集成验收 | 冻结代码树全量、完整成长/终局、关键横向玩法、安装与恢复、相应平台验收 | 测试失败后的新增代码或未解决风险，按实际影响补测 |

实际通过，以及新角色公开命令至渡劫 L10、飞升/留界的完整本地路径证据。B1 规则/来源、
B2/B3 真实平台/外部环境只阻断完整产品/正式发布，不能阻断这些已实现公开能力的本地验证。
文档协作者只执行文档门槛；主线负责启动和记录唯一一份业务长测。

快测覆盖受影响边界，不只跑新增测试；共享事务变更不能只验一个方便的入口。
允许按实际依赖列测试文件/节点，开工登记范围和理由，避免机械重复几百项相邻测试。
不为低影响可逆的文档调整新增镜像测试。

### 2.1 共享业务与适配器短合同

`runtime.create_runtime` 为所有接入构造同一个 `CommandRouter`、`XiuxianApplication`
与 `SQLitePlayerRepository`；`AdapterRegistry.dispatch` 校验适配器注册后直接调用同一 router。
适配器不能绕过 application 直接写仓库。完整成长、生产、战斗及结算等共享业务长链只运行
一份代表性路径，不因 QQ/OneBot 名称不同复制整条链；不能把传入两个平台字符串称为真实接入验收。

两端仍分别验证有差异的短合同：SDK 事件解析、群/私聊与频道场景、用户/机器人身份、
operation 与事件去重键、参数/权限映射、实际 handler 到 application 的接线、重试和错误映射；
消息层覆盖 QQ interaction ACK、msg_seq、Markdown/键盘及纯文本降级、OneBot 消息段与路由。
已有 `test_adapter_normalization.py`、`test_adapter_simulation.py` 与消息专项提供相应覆盖，
按改动选明确节点。发现平台特有业务分支或身份/权限差异影响业务时，补该分支的针对性用例，
不机械重跑另一个平台的完整成长。真实账号的连接与投递继续按 B2 单列。

代表性完整成长节点为
`test/test_progression_sources.py::test_shared_commands_can_reach_tribulation_l10_from_new_player`。
它保留 QQ 代表路径的全部成长、飞升和留界断言；两个终局复用同一公开成长状态。
仅移除相同共享调用链的 OneBot 重复执行；两端入口的短合同仍保留。

## 3. 可直接执行的命令

只改文档：

```bash
/root/myenv/bin/python -m pytest -q test/test_documentation.py
git diff --check
```

代码/内容的测试节点须由实际改动选择；下面是命令形状，不是要求每次全部运行：

```bash
/root/myenv/bin/python -m pytest -q <受影响的测试文件或节点>
/root/myenv/bin/python -m compileall -q nonebot_plugin_xiuxian_3
/root/myenv/bin/python -m pytest -q test/test_content.py
git diff --check
```

本地 M5/发布阶段全量：

```bash
/root/myenv/bin/python -m pytest -q --durations=20
```

内容检查须覆盖重复对象键、非有限数值、缺字段与坏引用，单独 `json.tool` 不能代替内容校验。
未配置的类型/静态检查不能只在文档中写“已通过”；使用现有检查入口并记录实际执行结果。

## 4. 长测纪律与证据复用

整仓全量及完整新角色成长/飞升等长链约需两小时，只在阶段验收或表中扩大条件成立时运行，
不因每个小修复、文档增写或提交前检查重复启动。
同一冻结代码树只运行一份对应长测，记录 PID/会话、命令、开始时间、日志、代码树/内容基线和结果；
其他代理复用记录，不启动平行副本。等待期间处理独立文档/验收，不阻塞所有工作。

全量若已包括成长长链，同一次结果同时提供证据，不另跑重复长链。
仅在所需玩家路径没有被覆盖时补明确节点；登记起点/夹具、真实命令、时间推进与路径终点。
中止、超时或未跑的长链均记未完成，不能用局部终局夹具替代新角色成长证据。

同一代码/内容/环境与相关边界没有变化，且没有新失败/未解问题时，不复跑已通过检查。
全量失败后先定性和定向修复/补验；扩大范围仅由新增变化或未解风险触发。
“首轮部分通过 + 失败项修后通过”是组合证据，不能改称最终代码树一次全量全通过。

当前 M5 出现真实失败时，先定位环境、夹具或实现根因，再做当前范围最小修复和定向回归；
不得新增 skip/xfail/ignore、取消测试收集、删除行为断言或降低验收阈值求通过。
影响业务行为、内容、环境或实际覆盖路径的变化，按影响补验；存在未解跨域风险时取得新全量证据。
纯文档或等价测试去重（仅移除重复路径，保留全部行为断言）不自动重跑整仓或完整成长。
此时记录运行时基线与提交树差异，用结构/断言等价核对、pytest 收集和受影响适配器短合同
证明证据仍适用；如改变夹具、命令、预期结果或覆盖分支，就不能以等价去重复用旧证据。
未完成、失败或拼接的局部结果不能改称一次最终全量通过。
仅补录验收结果、阻塞或其他无玩法变化的文档/AGENTS 时，补文档测试与 diff 检查即可，
保留未变业务树的全量/成长证据，不因此重复启动两小时长测。

## 5. 必要行为覆盖

资产写功能涉及的行为至少覆盖：正常成功、重复 operation、输入冲突、非法参数/权限、
资源/容量不足、状态/冷却/配额、随机冻结、并发、仓储故障回滚、重试和重启恢复；
影响入口时覆盖 QQ/OneBot 及文本/按钮共用 application。只读功能覆盖空数据、坏数据和权限。
关闭新建不影响历史快照与合法 operation 重放；损坏快照/账本拒绝时零写。

发布阶段核验：

- 空库/当前快照/重复/中断迁移，备份恢复，流水和 operation 重放一致且不重复发资产。
- 两次启动命令/任务/监听器不增加；NoneBot 安装与 QQ/OneBot fixture 验证准确命名。
- 内容全部稳定键/引用、可达来源、十层境界/跨境前置、配置实际消费和关闭入口闭合。
- 完整成长及飞升/留界、关键 PvE/PvP、生活/交易/社交/赛季恢复等冻结范围有证据。
- Web 写权限/会话/CSRF/路径、正式支付与跨服身份/资产隔离按各自合同与实际条件独立验收。
- QQ/OneBot 真实账号连接、文本/按钮 ACK、Markdown/纯文本降级需要真实平台记录；
  fixture、SDK 模拟或 `nb run` 启动不能代替。未具备条件则列 blocked，不自动开放/投产。

具体领域专项与合同保留在现有 `test/` 和领域文档，不在本页复制每个切片的历史结果。

skipped 不计通过；缺依赖/平台的必要测试保持待验收，正常条件分支跳过也单独披露。
文档、聚焦、全量、fixture/SDK 模拟、真实平台和完整成长证据分别标明，不能互相冒充。
正式发布条件不等于本地工程门槛；单个功能切片通过不能证明完整游戏或正式发布完成。
